# 案例反向改进记录

本案例用于检验规范、澄清流程和插件输出，不用于证明所有 CAD 需求都能一次处理完整。

## 从案例发现的规范改进点

1. CAD 批量操作必须检查“选择集范围、当前对象、只读/引用对象、部分成功和撤销粒度”，这些内容已纳入十二维中的范围、状态、异常和业务规则检查。
2. “按 CAD 现有规则”不能作为可执行规则，必须指出具体宿主约束或进入澄清。
3. 性能描述必须同时包含对象规模、选中规模、设备环境、计时边界和反馈方式。
4. 原型中控件存在不代表业务规则已确认，特殊对象和非法操作仍需产品经理决策。

## 从案例发现的流程改进点

1. 先确认操作范围，再询问当前图层和外部参照处理，避免候选项依赖关系混乱。
2. “部分成功”会影响反馈、撤销和验收，应作为高影响问题单独确认。
3. 性能阈值可以在核心规则稳定后询问，避免过早讨论实现指标。

## 后续插件改进项

- 在质量报告中固定展示十二维覆盖状态和 P0/P1 未决数量；
- 在校验器中检查六份固定文档、评分表、`UI-xxx`、稳定ID、澄清状态和追溯矩阵；
- 后续增加第二个 CAD 案例时，选择与几何命令、对象选择或文件兼容性相关的不同问题类型，检验规范的泛化能力。
