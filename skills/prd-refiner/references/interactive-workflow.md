# 交互式 PRD 优化工作流

本流程把 PRD 优化组织为十个可重复执行的环节。流程适用于任意格式的人工 PRD；输入不需要预先套用模板。每个环节都定义输入、操作、输出和进入下一环节的条件。

## 1. 显式启动

- **输入**：用户显式调用 `$prd-refiner` 或等效入口。
- **操作**：确认任务边界、工作语言、输出目录和是否允许写文件。
- **输出**：任务已启动、待提供资料清单。
- **门槛**：普通对话提到 PRD 不得自动启动。

## 2. 资料接收与来源登记

- **输入**：人工 PRD，以及可选表格、截图、Figma、Axure、会议记录或补充说明。
- **操作**：建立 `SRC-xxx` 来源清单，记录版本、位置、日期、可访问性和解析限制。
- **输出**：输入范围和缺失资料说明。
- **门槛**：原始 PRD 是必需输入；原型不可访问时允许降级，但必须记录限制。

## 3. 联合解析与需求建模

- **输入**：已登记的所有资料。
- **操作**：按 [prd-optimization-spec.md](prd-optimization-spec.md) 的十二维语义切分内容，标记证据类型，建立功能、规则、数据状态、非功能、验收和未决项草模；存在原型时按 [prototype-analysis.md](prototype-analysis.md) 分配 `UI-xxx` 并建立需求—页面—控件映射。
- **输出**：内部需求模型、原型观察、交互模型和来源映射。
- **门槛**：不得因原文没有固定章节而跳过维度。

## 4. 质量检查与问题发现

- **输入**：内部需求模型。
- **操作**：检查缺失、模糊、冲突、不可验证、无来源推断和追溯断点；按 P0–P3 标记影响等级。
- **输出**：问题清单及其来源、影响、依赖和候选处理方向。
- **门槛**：AI 可以提出候选方案，但不能把候选方案写成已确认规则。

## 5. 澄清队列排序

- **输入**：问题清单。
- **操作**：优先顺序为范围与目标、权限与关键规则、主流程、数据与状态、异常与边界、验收、非功能；同时考虑父子依赖、不可逆性和返工成本。
- **输出**：动态澄清队列。
- **门槛**：依赖父问题的子问题不得提前询问；每轮回答后重新排序，不预先固定全部批次。

## 6. Plan 模式交互澄清

- **输入**：当前最高优先级问题。
- **操作**：
  1. Codex 中先确认处于 Plan 模式；否则暂停并请用户切换。
  2. P0/P1、高影响、依赖性、权限、不可逆行为和会改变其他选项的问题单独询问。
  3. 仅将优先级相近、彼此独立、答案互不改变的 2–3 个问题合并。
  4. 材料足够时提供 2–3 个互斥候选项；推荐项排第一并说明影响。
  5. 允许自由输入实际规则；回答含糊时只追问对应问题。
- **输出**：每个问题独立的 `CL-xxx` 草稿。
- **门槛**：产品经理是业务决策最终来源；未确认内容保持待确认。

## 7. 决策记录与需求更新

- **输入**：产品经理回答。
- **操作**：记录来源、原始表述、问题、候选项、回答、最终决策、影响、状态和责任人；更新对应 `FR/BR/DATA/NFR/AC`。
- **输出**：更新后的需求模型和 `clarification-log.md`。
- **门槛**：即使同一轮确认多个问题，也必须生成独立 `CL-xxx`；需求修改需要反向关联澄清 ID。

## 8. 一致性复查

- **输入**：更新后的完整模型。
- **操作**：重新检查术语、数值、流程、权限、状态迁移、异常、PRD/原型对齐和需求/验收关联；确认早期答案是否改变后续候选项。
- **输出**：剩余问题和更新后的澄清队列。
- **门槛**：存在新的 P0/P1 问题时返回环节 5；不得为了结束流程而跳过复查。

## 9. 结构化输出

- **输入**：已确认结论和透明保留的未决事项。
- **操作**：按模板生成 `ai-ready-prd.md`、`interaction-spec.md`、`clarification-log.md`、`traceability-matrix.md`、`quality-report.md` 和 `evaluation-scorecard.md`；十二维没有信息时写“待确认”或“不适用及理由”。没有原型时，交互规格必须说明输入限制并记录PRD中可确认的交互或“不适用及理由”。
- **输出**：六份固定文档，以及有实际内容时的原型图片和图表资产。
- **门槛**：不得保留模板占位符；关键需求、规则、数据、非功能和验收必须使用稳定 ID。

## 10. 校验、评价与交付

- **输入**：六份输出文档及原始需求资料。
- **操作**：运行确定性校验；按 [evaluation-standard.md](evaluation-standard.md) 使用同一量表分别评价原始和优化后的需求；修复结构、编号和追溯问题。
- **输出**：通过校验的六文档需求包、优化前后评分、剩余风险和下一步建议。
- **门槛**：结构校验通过；P0 未决为零，或用户明确接受带风险交付。

## 异常与终止处理

- 产品经理暂时不能决定：标记待确认，记录责任角色或所需证据，继续处理独立问题。
- 原型或附件不可访问：记录解析限制，要求截图、导出文件或文字说明，不中断可继续的 PRD 优化。
- 用户要求跳过或直接输出：停止新增澄清，保留所有未决风险并进入环节 9。
- 用户要求终止：保存已确认决定和当前状态，不把未回答项写成确定需求。
- 校验脚本不可运行：执行等价人工检查，并在交付说明中记录限制。
