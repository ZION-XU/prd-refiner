# AI-Ready PRD 信息规范

本文件是执行时的快速参考。完整十二维定义、任意格式输入归一化、问题分级、编号追溯和交付门槛见 [prd-optimization-spec.md](prd-optimization-spec.md)；完整交互流程见 [interactive-workflow.md](interactive-workflow.md)。

## 证据与优先级

| 标记 | 含义 | 可否直接作为最终规则 |
|---|---|---|
| 原始事实 | PRD 正文、表格或附件明确陈述 | 可以，保留来源 |
| 原型观察 | 截图、可访问 Figma/Axure 或原型页面可见的界面、文案、状态 | 可以作为观察；与其他来源冲突时不可自行定论 |
| 产品经理确认 | 当前对话中对澄清问题的明确答案 | 可以，优先级最高 |
| AI 建议 | 基于资料提出的候选规则或实现建议 | 不可以，必须等待确认 |
| 待确认 | 缺失、模糊、冲突或无法解析的信息 | 不可以，保留风险和责任人（若已知） |

原型是辅助信息源，不等同于完整业务规则。PRD 与原型一致时可共同引用；仅一方存在时记录缺口；两者冲突时创建澄清项。不得默认“PRD 优先”或“原型优先”。

## 最小需求模型

| 对象 | 最小内容 | ID 示例 |
|---|---|---|
| 功能需求 | 角色、前置/触发、主流程、结果、优先级、来源 | `FR-001` |
| 业务规则 | 条件、判断、动作、结果、例外、关联功能 | `BR-001` |
| 数据或状态 | 实体/字段、约束、默认值、状态与允许迁移 | `DATA-001` |
| 非功能需求 | 适用范围、可测量条件或验收方式 | `NFR-001` |
| 验收标准 | Given/When/Then、预期结果、关联需求 | `AC-001` |
| 澄清决策 | 问题、候选项、回答、结论、影响和状态 | `CL-001` |

需求不是所有字段都必须“已确认”，但缺失信息必须显示为“待确认”，且不得从最终规则中悄悄省略。

## 质量判定

- **完整性**：目标、范围、角色、条件、流程、规则、异常、边界、状态、权限和验收是否足以理解。
- **清晰性**：避免“支持”“适当”“快速”“正常”“相关”等无法验证表述；若保留，定义条件或转为澄清项。
- **一致性**：术语、数值、权限、状态、PRD 与原型及章节间无未处理冲突。
- **可追溯性**：每个关键结论可回溯至原始资料或澄清 ID。
- **下游可消费性**：AI coding 或测试无需猜测主体、条件、行为、结果与例外。
