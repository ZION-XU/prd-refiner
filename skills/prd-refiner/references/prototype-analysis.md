# 原型输入、交互与冲突处理规范

当输入包含PRD内嵌截图、独立截图、Figma、Axure或其他可交互原型时，使用本规范建立需求—页面—控件映射。原型是重要证据，但不能替代产品经理对业务规则的确认。

## 1. 输入分级与能力边界

| 输入形式 | 基础处理 | 可能需要的额外能力 |
|---|---|---|
| PRD内嵌截图 | 读取可见文案、控件、状态和标注 | 文档解析、图片识别 |
| 独立原型截图 | 读取可见页面结构和静态状态 | 图片识别 |
| Figma导出文件 | 按可解析格式读取页面和资源 | 文件解析 |
| Figma在线链接 | 读取宿主能够访问的页面和节点 | 登录权限、API、MCP或连接器 |
| Axure截图 | 读取可见页面和状态 | 图片识别 |
| Axure HTML原型 | 遍历可访问页面和交互 | 浏览器交互能力 |
| Axure `.rp` 文件 | 不直接承诺完整解析 | 专用解析或先导出HTML/截图 |

按三级目标说明能力：基础为PRD加截图；进阶为可访问的Figma/Axure原型；扩展为API、MCP或专用连接器读取结构。无法访问时要求截图、导出文件或文字说明，并记录限制。

## 2. 原型证据提取

为页面、弹窗、面板或关键组件分配稳定 `UI-xxx` 编号，记录：

- 来源文件、页面、Frame、截图或URL；
- 入口、展现方式、关闭方式和跳转目标；
- 控件、字段、文案、默认值和可见/禁用条件；
- 默认、加载、成功、失败、空、禁用和权限不足状态；
- 提交条件、处理中反馈、成功结果和失败恢复；
- 关联的 `FR/BR/DATA/NFR/AC/CL`；
- 无法遍历、隐藏或用途不明的元素。

仅记录直接可观察内容。交互意图、业务约束和缺失状态可以作为问题或AI建议，不能直接标为已确认。

## 3. 多源冲突处理

| 情况 | 处理规则 |
|---|---|
| PRD与原型一致 | 同时作为来源，纳入候选需求 |
| 只有PRD描述 | 标记“原型未体现”，判断是否阻塞界面实现 |
| 只有原型体现 | 标记“PRD未定义”，进入澄清或确认其仅为展示 |
| PRD与原型冲突 | 创建独立 `CL-xxx`，不得自行指定任一方优先 |
| AI推导内容 | 标记“AI建议”或“待确认” |
| 产品经理确认 | 形成正式结论，并保留原始双方来源和澄清记录 |

最终优先级最高的是产品经理明确确认的结论，而不是笼统的“PRD优先”或“原型优先”。

## 4. 交互规格输出

在 `interaction-spec.md` 中按 `UI-xxx` 记录交互，不把大量控件状态塞入 `ai-ready-prd.md`。主PRD保留业务意图、关键规则和对 `UI-xxx` 的引用；交互规格承载页面级细节。

没有原型时也生成该文件：

- 明确写出“未提供原型”；
- 提取PRD中已经定义的入口、字段、操作、反馈和状态；
- 对未定义的交互标记待确认；
- 非界面需求可写“不适用及理由”，不得虚构 `UI-xxx`。

## 5. 追溯与资产

在 `traceability-matrix.md` 中建立：

`来源 ↔ FR/BR/DATA/NFR ↔ UI ↔ CL ↔ AC`

有原型图片、流程图或状态图时保存到：

- `assets/prototype-images/`
- `assets/diagrams/`

只保存用户授权处理的资料，不复制私有原型到插件仓库或公共位置。每个资产应在交互规格或追溯矩阵中被引用，未引用资产应标记用途或排除。
