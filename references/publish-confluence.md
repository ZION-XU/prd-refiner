# Confluence 交付与格式适配

仅在用户明确要求创建、更新、发布或同步到 Confluence 页面时读取。仅提供页面链接／ID 作为输入资料不表示写入授权；普通讨论、本地 Markdown 交付、只读检查不执行本流程。内容收敛和用户明确要求先出稿的规则仍遵循 Skill 入口。

## 写入目标与操作确认

**禁止自行选页写入、未经授权覆盖正文，或把来源页面当作默认输出目标。** “写到 Confluence”不自动确定页面；“更新／同步到这个页面”不自动授权整页替换。页面可访问、名称相似、搜索排名靠前、之前用过或看起来是空页，都不能替代用户指定或确认。目录层级指空间内的页面树，与正文 TOC 是两件事。

先完成可独立准备的正文、差异和拟写入方案，再就尚未明确的目标或操作向用户澄清。确认前可以只读核对候选位置，不能先创建草稿页面、修改正文、移动页面或上传附件。确认针对具体目标和范围；已有明确指令不重复确认，未答复或默认选项不算确认。

### 写入已有页面

读取用户指定地址／ID 对应的站点、空间、页面标题、父级路径、当前正文及版本，并在写入方案中展示实际页面链接和变更范围。无法读取或目标不匹配时停止写入，不找其他页面代替。

- **局部修改／追加**：明确修改哪些章节、插入位置及保留内容，依据最新正文生成合并结果；其余正文、宏、附件引用和历史记录保留。用户已明确例如“只更新第 5 章”时按该范围处理。
- **整页替换**：明确展示拟替换的正文、将删除或替代的范围及必要保留项，取得用户对该页面整页替换的明确授权。“用这份稿全文替换页面 X”可作为明确指令；笼统的“优化、更新、同步、写进去”不够，须澄清修改范围还是整页替换。
- 接口即使要求提交完整正文，也只能提交在授权范围内合并后的完整内容；技术上的全量提交不等于获得整页覆盖权限。改标题、移动父级、删除附件或子页面不包含在正文更新授权内。

### 新建页面或用户自行建页

结合需求所属产品／模块、版本及用户提示，在可读取的现有页面树中提出位置建议。展示站点、空间，以及“祖先页面 → 父页面 → 拟新建页面标题”的层级，已存在节点附真实链接／ID，新节点明确标为拟建。不能编造已有目录；父页面或空间无法核实时标明未知，请用户指定。

拟定的空间、父页面和标题须获用户确认后才创建。用户已明确指定三者并要求创建时，展示该层级后可按既有授权执行，无须重复提问。仅给出空间、需求名称或“找合适的位置”时，仍应展示具体层级方案并等待选择。不得为凑层级自动创建中间页面；每个拟新增页面都纳入确认范围。同名页面已存在时先澄清复用还是另建，不自动覆盖。

用户也可自行创建新页面，再提供写入地址。读取核对后写入其明确指定范围；若页面已含模板或其他正文，不因用户称其“新页面”便清空，仍按已有页面规则处理。澄清记录若需独立页面，也应在拟建层级中列出并获得对应授权，不能随主稿自动另建。

### 执行时保持确认范围

写入前核对实际目标 ID、父页面及最新版本仍与确认方案一致。出现并发修改时重新读取并核对差异；仅在原授权范围仍明确且不会丢失他人内容时重新合并，影响范围改变则再次澄清。创建或写入响应不确定时先只读检查是否已成功，不能盲目重试造成重复页；失败后不擅自更换空间、父页面或目标页面。已有授权只对原目标和操作范围有效。

## 格式适配

按已确认目标及宿主实际可用工具交付，复用已有 MCP、连接器、API 或浏览器能力，不强制使用某种工具。

先检查实际工具接受的正文格式和转换能力。工具能正确处理 Markdown 和所需宏时直接复用；仅在接口支持且需要时生成 Storage Format，并使用对应格式参数，避免已转换内容被二次转换或以源码显示。Storage Format 是含 Confluence 自定义元素的 XML，不等同任意 HTML；其他编辑器格式按当前接口处理。[官方格式说明](https://confluence.atlassian.com/doc/confluence-storage-format-790796544.html)

编制与修订人按 [内容标准](prd-standard.md)记录；工具支持版本说明时填写本次实际变化。独立澄清记录的触发、内容与交付边界按 [工作流](workflow.md#澄清决策记录)执行。

## 目录与布局

目录采用原生 `toc` 宏，不把 Markdown 标题哈希列表机械转换为页面目录。目录参数根据实际标题层级设置：正文保留总标题 h1、章节从 h2 开始时用 `minLevel=2`；移除正文重复总标题或改变层级后相应调整。`maxLevel` 通常为 3 或 4，以实际需要为准；目录自身的标题不要重复收入目录。原生目录按当前页面标题生成，仍需检查实际跳转。[官方目录说明](https://support.atlassian.com/confluence-cloud/docs/insert-the-table-of-contents-macro/)

默认保留全宽正文，优先考虑右上角可折叠目录，避免长表格被常驻侧栏挤窄。按目标环境能力选择：

1. **全宽正文＋折叠悬浮目录**：仅在目标已有并允许使用 `zwFloatingTocRight` 样式、外层容器及 `expand` 嵌套目录可用时采用。该类名来自中望测试副本，是环境依赖，不是 Confluence 通用保证。先核对现有页面或可读样式及渲染效果，不自行安装样式或改变站点配置。
2. **双栏侧栏**：仅用户明确偏好双栏时采用，确认宽表格仍可阅读；支持 Storage 布局时可使用 `two_right_sidebar`，正文与目录分置两个单元格。
3. **正文内目录**：样式不可确认、容器被过滤、宏嵌套不支持或悬浮遮挡内容时，使用正文内原生目录；可折叠能力单独确认后按需保留。不为获得悬浮效果绕过站点限制。

支持 Storage Format 且满足上述样式前提时，折叠目录可采用以下结构；坐标和宽度按实际页面调整，不能仅凭写入成功认定悬浮生效：

```xml
<div class="zwFloatingTocRight" style="top: 120px; right: 20px; width: 280px; background: #fff; padding: 8px 12px;">
  <ac:structured-macro ac:name="expand" ac:schema-version="1">
    <ac:parameter ac:name="title">页面目录（展开／折叠）</ac:parameter>
    <ac:rich-text-body>
      <ac:structured-macro ac:name="toc" ac:schema-version="1">
        <ac:parameter ac:name="minLevel">2</ac:parameter>
        <ac:parameter ac:name="maxLevel">3</ac:parameter>
      </ac:structured-macro>
    </ac:rich-text-body>
  </ac:structured-macro>
</div>
```

正文内目录的 Storage 示例：

```xml
<ac:structured-macro ac:name="toc" ac:schema-version="1">
  <ac:parameter ac:name="minLevel">2</ac:parameter>
  <ac:parameter ac:name="maxLevel">3</ac:parameter>
</ac:structured-macro>
```

## 条目名称与页内引用

正文遵循 [名称、概述与跳转](prd-standard.md#名称概述与跳转)：标题、表格定义项及引用均用“名称（编号）”，引用处保留理解当前场景所需的概述。目录只能帮助浏览章节，不能替代条目之间的引用链接。

优先复用目标页面实际支持的标题链接或显式锚点，把引用链接到规则的唯一完整定义。支持显式锚点时可使用由稳定编号派生的标识，如 `br-001`；创建和引用方式须按实际编辑器、接口及已有页面能力核对，不把 Markdown 的 `#br-001` 或标题哈希直接视为 Confluence 可用地址。转换正文后重新核对目标，保留授权范围内仍有效的已有锚点。

表格条目优先定位到行内可用锚点；若不支持则链接到所属小节，显示名称和编号便于查找。无法提供可靠跳转时保留“名称（编号）＋所在章节”，说明跳转限制，不生成看似可点击但目标不明的链接。局部更新只改授权范围内的名称、概述与链接，范围外失效引用列为待处理项。

## 表格、图片与代码

- 表格保留真实表头、行列和换行，手动生成 Storage 时使用规范的 `table`、`tr`、`th`、`td` 结构；可沿用目标已有的 `wrapped` 等样式，不把样式类视为跨环境保证。不要为美化改写规则含义或丢失单元格内容。
- 优先复用仍可访问的已有附件引用；新增本地图片用当前可用的附件接口上传后引用实际附件。Storage 可使用 `<ac:image><ri:attachment ri:filename="实际文件名.png" /></ac:image>`；引用其他页面附件时带上真实页面上下文。不能把本地绝对路径或臆造的下载地址写成平台图片；取得与核对遵循 [图片规范](prototype-analysis.md)。
- 代码按当前编辑器支持使用代码块或 `code` 宏，保留换行及原文。手工生成 XML 时正确转义正文与属性，不把普通 HTML 当作宏，不重复转义工具已处理的内容。

## 写入后核对

使用现有授权能力回读页面，核对正文、表格、修订信息、宏、条目引用及附件引用；能查看渲染时检查目录和条目链接实际跳转、折叠、滚动遮挡和图片显示。按本次采用的标题／表格锚点方式检查代表性引用，确认落在对应定义，重点核对改名或移动的条目。样式失败按上述条件降级，不反复提交同一失败布局。无法查看时明确哪些仅完成存储核对、哪些显示行为未验证，不声称跳转或悬浮已验证。

提供真实页面链接及实际交付结果。内容质量、写入成功和渲染可用分别判断；工具缺失、权限不足或写入失败时保留可复制内容并说明未完成部分，不把发布成功等同正式评审通过。
