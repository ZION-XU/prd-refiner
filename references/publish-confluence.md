# Confluence 交付与格式适配

仅在用户明确要求新建、修改、追加、发布或同步到 Confluence 页面时读取。本文“写入”包括新建与修改；仅提供页面链接／ID 作为输入资料不表示授权修改。普通讨论、本地 Markdown 交付、只读检查不执行本流程。内容收敛和用户明确要求先出稿的规则仍遵循 Skill 入口。

## 写入目标与操作确认

**禁止自行选页写入、未经授权覆盖正文，或把来源页面当作默认输出目标。** “写到 Confluence”不自动确定页面；“更新／同步到这个页面”不自动授权整页替换。页面可访问、名称相似、搜索排名靠前、之前用过或看起来是空页，都不能替代用户指定或确认。目录层级指空间内的页面树，与正文 TOC 是两件事。

先完成可独立准备的正文、差异和拟写入方案，再就尚未明确的目标或操作向用户澄清。确认前可以只读核对候选位置，不能先创建草稿页面、修改正文、移动页面或上传附件。确认针对具体目标和范围；已有明确指令不重复确认，未答复或默认选项不算确认。

### 修改已有页面

读取用户指定地址／ID 对应的站点、空间、页面标题、父级路径、当前正文及版本，并在写入方案中展示实际页面链接和变更范围。无法读取或目标不匹配时停止写入，不找其他页面代替。

- **局部修改／追加**：明确修改哪些章节、插入位置及保留内容，依据最新正文生成合并结果；其余正文、宏、附件引用和历史记录保留。用户已明确例如“只更新第 5 章”时按该范围处理。
- **整页替换**：明确展示拟替换的正文、将删除或替代的范围及必要保留项，取得用户对该页面整页替换的明确授权。“用这份稿全文替换页面 X”可作为明确指令；笼统的“优化、更新、同步、写进去”不够，须澄清修改范围还是整页替换。
- 接口即使要求提交完整正文，也只能提交在授权范围内合并后的完整内容；技术上的全量提交不等于获得整页覆盖权限。改标题、移动父级、删除附件或子页面不包含在正文更新授权内。

### 修改方式与版本差异

单章修改先检查并优先使用 `confluence_update_page_section`（或宿主等价工具），精确匹配标题，仅提交标题下正文；含宏时用 `content_format="storage"`。局部工具不可用或无法准确定位时，才考虑基于最新 Storage 合并后全量提交；保留范围外原始表示，禁止为局部修改整页往返转换 Markdown 或统一排版。整页重构须有明确授权。

根据宿主实际能力选择工具，不依赖固定名称。当前 Atlassian MCP 的对应能力可作为参考：

| 操作 | 工具示例与使用要点 |
|---|---|
| 新建页面 | `confluence_create_page`：指定空间、父页面和标题 |
| 修改一个章节 | `confluence_update_page_section`：按原始标题精确定位，提交标题下的新正文；重复标题或定位不唯一时不猜测匹配，改用可唯一定位的方式；章节内未要求修改的内容仍保留 |
| 合并后更新页面 | `confluence_update_page`：保持同一 page ID，提交基于最新正文的合并结果；保留未要求更改的标题和其他属性 |
| 核对版本差异 | `confluence_get_page_diff`：指定 page ID、修改前版本和修改后实际版本 |
| 读取历史版本 | `confluence_get_page_history`：读取指定版本；核对宏和结构时优先原始格式 |

修改前记录实际版本，提交时填写准确的 `version_comment`（工具支持时），修改后回读取得实际版本号，不假定它一定是旧版本加一。用版本差异工具核对本轮变更是否符合授权范围，识别无关内容丢失、链接变化或格式重排；工具不可用或 diff 隐藏宏与格式时，对照前后 Storage，并说明检查边界。出现并发编辑时区分他人改动，不自动恢复旧版覆盖当前内容；本轮意外变更仅在范围仍明确时基于最新正文修正。

Confluence 保留页面版本并支持比较；全量提交正文不会自动使 diff 失效，但重新生成未改内容可能扩大差异、掩盖实际需求变更。目标是让可见差异对应本次修改，不以删历史、删页重建或另建同名页实现更新。[官方版本历史与比较说明](https://confluence.atlassian.com/doc/page-history-and-page-comparison-views-139379.html)

### 新建页面或用户自行建页

结合需求所属产品／模块、版本及用户提示，在可读取的现有页面树中提出位置建议。展示站点、空间，以及“祖先页面 → 父页面 → 拟新建页面标题”的层级，已存在节点附真实链接／ID，新节点明确标为拟建。不能编造已有目录；父页面或空间无法核实时标明未知，请用户指定。

拟定的空间、父页面和标题须获用户确认后才创建。用户已明确指定三者并要求创建时，展示该层级后可按既有授权执行，无须重复提问。仅给出空间、需求名称或“找合适的位置”时，仍应展示具体层级方案并等待选择。不得为凑层级自动创建中间页面；每个拟新增页面都纳入确认范围。同名页面已存在时先澄清复用还是另建，不自动覆盖。

用户也可自行创建新页面，再提供写入地址。读取核对后写入其明确指定范围；若页面已含模板或其他正文，不因用户称其“新页面”便清空，仍按已有页面规则处理。澄清记录若需独立页面，也应在拟建层级中列出并获得对应授权，不能随主稿自动另建。

### 执行时保持确认范围

写入前核对实际目标 ID、父页面及最新版本仍与确认方案一致。出现并发修改时重新读取并核对差异；仅在原授权范围仍明确且不会丢失他人内容时重新合并，影响范围改变则再次澄清。创建或写入响应不确定时先只读检查是否已成功，不能盲目重试造成重复页；失败后不擅自更换空间、父页面或目标页面。已有授权只对原目标和操作范围有效。

## 格式适配

按已确认目标及宿主实际可用工具交付，复用已有 MCP、连接器、API 或浏览器能力，不强制使用某种工具。

本 Skill 的 Confluence PRD 最终提交统一使用 **Storage Format**，设置 `content_format=storage`（或宿主等价参数）；不把 Markdown 直接提交并依赖服务端自动锚点映射。已有 Markdown 转换器可用于生成待检查的 Storage，但转换后须按下文修正并校验锚点与目录，不重复转换。接口无法提交 Storage 时保留本地稿并说明发布受限，不静默改用 Markdown 直发。Storage 是含 Confluence 自定义元素的 XML，不等同任意 HTML。[官方格式说明](https://confluence.atlassian.com/doc/confluence-storage-format-790796544.html)

写入前依次执行：**保存并回读工作区 Markdown → 准备最终 Storage → 配对编号引用与定义锚点 → 装配浮动折叠目录 → 运行组合交付检查 → 提交同一份已检查正文 → 回读再检查。** 本地落盘、图片与明确仅远程例外按 [工作流](workflow.md#保存状态与失败)。局部修改在最新原始 Storage 中合并授权片段，不为执行转换流程重排整页；范围外缺陷只报告，不能为通过全稿检查擅自修复。

编制与修订人按 [内容标准](prd-standard.md)记录；工具支持版本说明时填写本次实际变化。独立澄清记录的触发、内容与交付边界按 [工作流](workflow.md#澄清决策记录)执行。

## 目录与布局

目录采用原生 `toc` 宏，不把 Markdown 标题哈希列表机械转换为页面目录。目录参数根据实际标题层级设置：正文保留总标题 h1、章节从 h2 开始时用 `minLevel=2`；移除正文重复总标题或改变层级后相应调整。`maxLevel` 通常为 3 或 4，以实际需要为准；目录自身的标题不要重复收入目录。原生目录按当前页面标题生成，仍需检查实际跳转。[官方目录说明](https://support.atlassian.com/confluence-cloud/docs/insert-the-table-of-contents-macro/)

新稿默认交付**全宽正文＋右上浮动折叠目录**。中望站点采用下述已实测方案；用户明确要求正文目录或全文双栏时按其选择。文首用于定位的两栏不等于全文双栏，局部修改既有页面时，目录变更仍受授权范围约束。

读取并套用 [原生布局骨架](../assets/confluence-toc.xml)：

- 文首 `two_right_sidebar`：左格放文档信息和修订表，右格放整个 `div.zwFloatingTocRight → expand → rich-text-body → toc`。浮动类挂在折叠容器外层，不能只挂到内部 `toc`，否则折叠按钮与列表可能分离。
- 后续 `single`：放全部章节正文，保持全宽。用已准备的 Storage 片段分别替换 `{{FRONT_MATTER_STORAGE}}`、`{{BODY_STORAGE}}`，不再转义为文字；文首为空时放 `<p><br/></p>`。已有 `ac:layout` 时在原结构中合并，不嵌套第二套布局或重复正文。
- 外层容器只保留类名，去掉内联 `position/top/right/left/bottom` 和尺寸装饰补丁。右侧原生格确定起始位置，站点样式负责固定浮动；编辑器可以保留原生布局、类名和宏，普通改标题不再依赖被清理的内联坐标。不要把右侧格移到正文末尾或把主正文放进文首左格。

按实际章节调整 `minLevel/maxLevel`，默认排除“目录”自身标题，移除旧静态目录列表并保留相邻内容。修改已有页只调整授权布局；用原始 Storage 片段迁移内容，保留宏 ID、附件及编号锚点。

适用前提是目标站点已有 `zwFloatingTocRight` 样式；它不是 Confluence 通用内置类。[站内实现说明](https://confluence.zwcad.com/pages/viewpage.action?pageId=110925610)与[使用说明](https://confluence.zwcad.com/pages/viewpage.action?pageId=190089634)说明了该类的用途。

新站点先核对已有样式或等价机制，缺少时说明依赖并提出可用方案，不自行改空间／全局 CSS，也不回退到正文内联坐标。不可用时报告未完成，正文目录只作为用户可选替代。检查用于确认生成方案有效，不能用新增验收条款替代修复。

仅在用户明确选择正文目录时，可使用以下结构；这不满足默认浮动折叠要求：

```xml
<ac:structured-macro ac:name="toc" ac:schema-version="1">
  <ac:parameter ac:name="minLevel">2</ac:parameter>
  <ac:parameter ac:name="maxLevel">3</ac:parameter>
  <ac:parameter ac:name="exclude">^目录$</ac:parameter>
</ac:structured-macro>
```

## 条目名称与页内引用

正文遵循 [名称、概述与跳转](prd-standard.md#名称概述与跳转)：标题、表格定义项及引用均用“名称（编号）”，引用处保留理解当前场景所需的概述。目录只能帮助浏览章节，不能替代条目之间的引用链接。

新稿按当前定义建立“编号 → 名称 → 唯一目标”对应，目标统一采用小写稳定编号，如 `fr-001`、`br-001`。Markdown 的 `<a id="fr-001"></a>` 与 `[名称（FR-001）](#fr-001)`，在 Storage 中必须生成下面成对的原生宏；不依赖全文标题 slug 自动映射。先定位完整定义，再生成引用，不能把功能索引当定义，也不能只修 FR 而遗漏 BR、AC、DEC 等表格或列表条目。转换后出现 `ac:anchor="fr-001"` 却只有 `名称fr-001` 的目标，必须修复后才能发布。

局部修改保留范围外已有锚点和表示；可在授权定义处增加稳定别名，保留原有效标题锚点以兼容旧链接。检查每个目标唯一且指向同一条目的完整定义，不用全局字符串替换改写无关链接。定义处不在授权范围内时报告需联动的位置，不擅自扩展修改范围。

使用 Storage Format 时，按以下方式成对创建定义锚点和同页链接。定义处用 `anchor` 宏，引用用 `ac:link ac:anchor`，二者标识完全一致；不要在索引上重复放置定义锚点。[官方链接格式](https://confluence.atlassian.com/doc/confluence-storage-format-790796544.html)、[官方锚点宏示例（5.9 文档）](https://confluence.atlassian.com/conf59/anchor-macro-792499068.html)。示例说明存储语法，实际目标站点仍须回读并核对跳转。

```xml
<!-- 引用处，例如第 2 章范围 -->
<p><ac:link ac:anchor="fr-001"><ac:plain-text-link-body><![CDATA[直线计数（FR-001）]]></ac:plain-text-link-body></ac:link>：显示所选直线数量，其他对象不计入。</p>

<!-- 功能的唯一完整定义处 -->
<ac:structured-macro ac:name="anchor" ac:schema-version="1">
  <ac:parameter ac:name="">fr-001</ac:parameter>
</ac:structured-macro>
<h3>直线计数（FR-001）</h3>
<p>用户点击计数后显示数量；详见<ac:link ac:anchor="br-001"><ac:plain-text-link-body><![CDATA[计数对象范围（BR-001）]]></ac:plain-text-link-body></ac:link>。</p>

<!-- 表格行中的规则定义目标 -->
<table><tbody><tr><th>规则名称（编号）</th><th>行为</th></tr>
<tr><td><ac:structured-macro ac:name="anchor" ac:schema-version="1"><ac:parameter ac:name="">br-001</ac:parameter></ac:structured-macro>计数对象范围（BR-001）</td><td>仅统计所选直线，没有直线显示 0。</td></tr>
</tbody></table>
```

多个条目分别生成链接，引用标签采用定义中的名称（编号）。转换器丢弃显式锚点、改写目标或产生重复目标时，修复待提交 Storage 并重新检查；不能以转换器报告成功替代检查。

表格条目优先定位到行内可用锚点；若不支持则链接到所属小节，显示名称和编号便于查找。无法提供可靠跳转时保留“名称（编号）＋所在章节”，说明跳转限制，不生成看似可点击但目标不明的链接。局部更新只改授权范围内的名称、概述与链接，范围外失效引用列为待处理项。

## 图示、表格与代码表达

生成的 Confluence PRD 默认不使用 `code` 或 `noformat` 宏，尤其不能用 ASCII 字符框、箭头和空格拼原型、流程或故事地图。图示直接使用可编辑的原生排版或已渲染图片；真实代码短片段可用行内代码，长片段保留原文为单独附件并引用。已有页面局部修改只处理授权范围内的宏，范围外问题提示，不为了去宏删除必要内容。此规则约束交付页面，不要求删除 Skill 文档中的 XML 示例代码块。

故事地图先按 [二维建模方法](specify.md#总体流程与用户故事地图)组织内容。可用原生 `section`／`column` 分栏及 `panel` 卡片表达：跨行列宽一致，故事对应上方任务，交付切片横贯相关活动，保留功能跳转；不固定列数、配色或卡片数量。也可使用表格或已渲染图像，排版不能代替二维关系。

不假定独立 HTML 的 CSS Grid/Flex、脚本或控件能在 Confluence 编辑保存后保留。需精细排版时可保留源文件并渲染成图，图旁另放功能链接；图片中文字不会自动成为页内链接。图片按 [图片规范](prototype-analysis.md)交付，避免代码宏不等于已解决目录遮挡。

- 表格保留真实表头、行列和换行，手动生成 Storage 时使用规范的 `table`、`tr`、`th`、`td` 结构；可沿用目标已有的 `wrapped` 等样式，不把样式类视为跨环境保证。不要为美化改写规则含义或丢失单元格内容。
- 优先复用仍可访问的已有附件引用；新增本地图片用当前可用的附件接口上传后引用实际附件。Storage 可使用 `<ac:image><ri:attachment ri:filename="实际文件名.png" /></ac:image>`；引用其他页面附件时带上真实页面上下文。不能把本地绝对路径或臆造的下载地址写成平台图片；取得与核对遵循 [图片规范](prototype-analysis.md)。
- 手工生成 XML 时正确转义正文与属性，保持必要代码片段的字符和换行，不把普通 HTML 当作宏，不重复转义工具已处理的内容。

## 写入后核对

修改已有页面时，先按“修改方式与版本差异”核对实际前后版本及修改范围；新建页面核对新页面的 ID、位置与正文，不要求不存在的旧版本 diff。

写入前及回读后，按 [交付检查](review.md#交付检查)运行 `validate_delivery.py`；使用实际保存的本地 Markdown 和本次最终／回读 Storage 文件，不复用修改前的通过结果。它检查本地落盘、两种格式的引用，以及目录的右侧原生布局、整组浮动容器和后续全宽正文，不再要求内联定位。新完整稿存在错误时先修复，不继续普通发布；局部修改的范围外旧问题单独报告，不借检查扩权，也不宣称全页合格。

另行核对两种格式的正文、表格、版本与附件，脚本只对照定义编号集合，不能证明语义一致。能查看渲染时检查目录和条目链接实际跳转、折叠、滚动遮挡和图片显示，至少覆盖范围、功能索引、规则引用、验收关联及表格目标中的适用类型。无法查看时明确“Storage 静态检查通过，点击和浮动效果未验证”；失败或缺能力不能标记三项交付全部完成。

提供真实页面链接及实际交付结果。内容质量、写入成功和渲染可用分别判断；工具缺失、权限不足或写入失败时保留可复制内容并说明未完成部分，不把发布成功等同正式评审通过。
