# 需求探索与分片推进 (PRD Explore)

## 一、 跨周多会话并发与状态感知（无线性锁）

大型 CAD 需求通常持续数周、横跨数十个会话，且常在多个会话窗口中并发推进不同功能（FR）。本 Skill 不设强制串行锁，而是通过 **工作区物理分片状态** 自然感知进度：

| 资产路径 | 职责与内容 | 并发读写规则 |
|---|---|---|
| `00_需求总览.md` | 承载文档头、第 1~2 章（背景、目标、范围）、第 3.1 节 **功能清单总表（含各 FR 状态）** 及第 4~7 章全局尾部 | 仅在全局规划或合龙阶段更新，单功能会话不直接覆写 |
| `features/FR-xxx_<名称>/prototype.html` | 基于 `Nova-proto` `<cad-*>` 组件库构建的可运行交互原型（顶部内嵌方案取舍洞察卡片） | **单会话独占读写**，不同会话各改各的 FR 目录，零冲突 |
| `features/FR-xxx_<名称>/spec.md` | 由定稿 `prototype.html` 与已确认 CAD 规则提炼出的单功能内聚规格（含入口、交互卡、BR、AC） | **单会话独占读写**，原型确认后生成 |
| `Missing_Components.md` | 汇总各 FR 原型中标记为 `status="draft"` 的缺失组件提单，供 UI 设计师在 Figma 补齐 | 按 FR 归属追加，或由 `scripts/assemble_prd.py` 自动扫描生成 |

- **新会话快速续接**：新开会话时，AI 先读取工作区下的 `00_需求总览.md` 与 `features/` 目录结构，识别哪些 FR 尚缺 `prototype.html` 或 `spec.md`，直接定位到用户指定的单个 FR 开展工作，无需加载其他无关分片。
- **确认后入稿**：单个 FR 的机制方案与 `prototype.html` 获 PM 确认后，立即提炼写入该分片的 `spec.md`；当需要产出完整 PRD 时，运行 `scripts/assemble_prd.py` 将 `00_需求总览.md` 与所有已就绪的 `features/FR-*/spec.md` 一键合龙为 `<需求名>.md`。

## 二、 第一性归零推演（拒绝做题家式平移）

在着手编写某个核心 FR 的 `prototype.html` 前，严禁对既有软件旧界面或输入材料做被动平移，必须穿透以下四问完成方案破局：

1. **意图剥离（Intent vs. Mechanism）**：剥离“CAD 设计师的真实图纸终态意图”与“既有按钮/弹窗/向导步骤”。抹去历史操作流，直接定义不可削减的业务终态。
2. **前提审计（Premise Audit）**：既有繁琐交互建立在当年哪些历史限制（旧架构、模态阻塞、算力或控件局限）之上？这些假设在现代 Qt5 / Nova 架构下是否已失效？
3. **极限动线（Zero-Friction Limit）**：推导从触发命令到图元落盘的最短操作路径。审视每一个单选、弹窗与跳转：能否合并为同一视图下的实时预览与智能默认？
4. **参谋反转与原型内嵌（Insights in Prototype）**：主动向 PM 提出【代差方案】（旧实现痛点 vs 新方案最短路径），经 PM 拍板后，将核心论据直接写入该功能 `prototype.html` 顶部的 `.design-insights-card` 面板中，使设计理由与交互原型永久同源绑定，不再散落于外部探讨草稿。
