# 需求探讨与分片推进

用于和产品经理（PM）一起理清功能思路、找到最优交互方案，以及在大型需求中跨多个会话并行推进。

## 一、 怎么把功能想透（不盲目照搬旧做法）

当 PM 提出做一个功能（比如“快速选择”、“创建表格”）时，不要上来就把传统 CAD 软件二十年前的老弹窗照搬过来。按下面 3 个最朴素的问题去想：

1. **设计师为什么要做这个操作？他的下一步是什么？**
   - 用户嘴上说的往往只是一个中间动作（比如“我要快速选中这些图元”、“我要画个表格”）。
   - 往深问一层：**他选完之后要干嘛？他的数据原本在哪？**
     - 比如“快速选择”：是为了选出来一次性改颜色/删掉，还是为了在复杂图纸里统计数量，或者每天都要重复这套筛选？
     - 比如“创建表格”：数据其实早就在 Excel 里写好了，还是在图纸现有的图块里要汇总统计，还是真的要手画空表？
     - **目的和数据来源不同，最顺手的做法就完全不同。**

2. **以前的做法笨在哪里？**
   - 看看既有软件或旧版操作里，有哪些让设计师觉得烦的地方：
     - 是不是本来一步能干完的事，非要连弹三四层窗口？
     - 是不是有足足七八步的向导，甚至还没干活先逼用户存一个配置文件？
     - 是不是只让用户填一堆抽象数字（如列宽 50、行高 8），没有实时预览，放到图纸上才发现大小完全不对？
     - 是不是关掉窗口后上次设好的条件就全丢了，下次还得重填一遍？

3. **能不能用更少的步骤、更直观的方式解决？**
   - 能不开弹窗直接完成吗？（比如直接复制粘贴、拖拽文件、或者画布上直接点选）
   - 如果需要弹窗，能不能做到**“一个窗口搞定，左边改条件、右边实时看到结果，不弹二级子窗口”**？
   - 把这些想法用大白话整理成 1~2 个清晰的方案跟 PM 讨论，把利弊讲明白，由 PM 拍板。

---

## 二、 大型需求怎么分片推进（多会话互不干扰）

如果是一个简单的单文件 PRD 或只改一两个小地方，直接改主文档即可。
如果是包含很多个子功能（FR）、需要分好几天或开多个窗口同时打磨的大型需求，可以把每个功能拆到独立文件夹里推进：

| 文件路径 | 放什么内容 | 怎么用 |
|---|---|---|
| `00_需求总览.md` | 文档头、第 1~2 章（背景、目标、范围）、第 3.1 节功能清单总表、第 4~7 章 | 全局规划或最后合龙时更新 |
| `features/FR-xxx_<名称>/prototype.html` | 该功能的 `<cad-*>` 界面原型 | 单个会话只改当前负责的 FR 文件夹，不碰别的文件夹 |
| `features/FR-xxx_<名称>/spec.md` | 该功能的规格说明（命令入口、重点交互逻辑、底层规则 `BR`、验收标准 `AC`） | 原型确认后提炼写入 |
| `Missing_Components.md` | 各原型里标记了 `status="draft"` 的缺失组件汇总表 | 供 UI 设计师在 Figma 里补充新组件 |

- **接手新任务时**：先看一眼工作区里的 `00_需求总览.md` 和 `features/` 目录，找到 PM 当前指定要做的那个功能文件夹直接干活。
- **需要生成完整 PRD 时**：运行 `scripts/assemble_prd.py`，把 `00_需求总览.md` 和所有 `features/FR-*/spec.md` 自动拼接成完整的 `<需求名>.md`。
