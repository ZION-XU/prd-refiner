# 需求探索与机制击穿 (PRD Explore)

## 一、门禁与台账（唯一完整定义）

门禁记录用户决策事实，非模型推断：

| 台账 id | 确认内容 | 通过判据 |
|---|---|---|
| **macro** | 宏观范围与形态 | 宏观四项（用户与角色、背景与现状痛点、目标与成功判据、范围与非目标）已获用户确认 |
| **fr** | 核心 FR 机制击穿 | 本期核心 FR 清单明确，每个关键 FR 的机制候选与代价已获用户裁决 |
| **scope** | 成稿范围与结构 | 已报拟成稿的范围与结构并获用户确认 |
| **review** | 下游审查与消缺 | 四视角下游断点排查与消缺已完成，已交互确认关键决断，达成可交付标准 |

- **留痕与续接**：确认后立即调用 `scripts/gate_state.py --workspace <绝对路径> --clear <id> --evidence "..."` 记账（用户要求直接出稿用 `--waive`，换需求用 `--reset`）；续接未完成需求先 `--workspace <绝对路径> --read`。
- **顺序与复位**：四处按 macro → fr → scope → review 依次记账，前序未记不得跳记后序；`--waive` 后不再接受 `--clear`，换需求用 `--reset`。
- **成稿与交付底线**：macro/fr/scope 三处确认齐备（或已 waive）是成稿前提；满足后按 [成稿与交付](delivery.md) 成稿并执行静态校验；随后按 [下游审查清单](downstream-review.md) 完成四视角审查与消缺并取得 review 确认，方可正式交付或发布 Confluence。

## 二、推演与击穿方法

- **探讨与正文分离**：正文只写“是什么”；候选对比、被否理由与取舍代价沉淀至 `<需求名>_需求探讨.md`。
- **基准与未决**：以用户输入的原始材料（整理的资料、原型、快照或灵感）为基准，明确本期目标与非目标；探索中出现的未决项不当结论写死，其确认状态与去向统一依 [内容约定](prd-standard.md)。
- **关键机制重解（严禁凭先验惯性默写竞品旧实现）**：
  - **交出机制候选**：候选之间必须是机制差异而非参数微调，交出代价与推荐倾向；
  - **穿透历史妥协**：回答我们自己的旧实现当年妥协了哪条约束，该约束今天是否依然成立；“所以然”的构成见 [竞品对标](prd-benchmark.md) §4。
  - **重推判据**：候选相比既有做法，在形态、时序、输入、信息架构或规模退化上至少有一处改变，并回答“去掉这一步会怎样”。
