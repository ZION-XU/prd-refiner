# 下游视角审查

用于在成稿或审查时，从下游落地执行角色的视角发现断点，避免进入研发和测试时返工扯皮。

沿用户实际操作流程，按本次范围检查下游关键痛点：

| 视角 | 下游开工时的核心痛点（没有就会扯皮） | 重点排查 |
|---|---|---|
| **研发** | **“我必须靠猜才能写代码”** | 前置条件与对象限制（如锁定图层/无效图元）、中断与退出处理（ESC/取消/崩溃）、撤销重做（Undo/Redo）边界、老图纸与历史兼容 |
| **品质 (QA)** | **“没有明确对错标准，我没法写用例”** | 预期结果是否客观可量化、异常分支与反例数据是否缺失、验收条件是否与功能规则一一闭环（不得凭空加新要求） |
| **交互与设计** | **“操作走不通，界面图文打架”** | 操作流程是否有断点、界面控件与实际原型图片是否一致（严禁脑补路径）、状态反馈与错误提示文案是否明确 |
| **产品化交付** | **“发布上线时漏了配套项”** | 命令别名/多语言资源、帮助文档入口、外部配置或模板依赖 |

### 处置原则
- **事实性问题**（如原型与文字冲突、漏写已有命令）：直接依据真实依据修正。
- **业务性决断**（下游必须知道但资料未决定的规则）：提炼为带默认建议的待确认项（DEC），一次性向产品澄清或标注保留。
