# 下游审查与消缺规范

成稿后、交付或发布前在面向用户的主会话中执行，对应 `review` 门禁（不另启子智能体，以便在排查发现断点时直接与用户交互澄清并就地消缺）。用于排查研发、品质 (QA)、交互与产品化四视角的落地断点，并通过自动修正或交互确认就地消缺，消除所有模糊与悬空项。本清单为客观规则完备性自检表，无需在会话中进行多角色人格扮演。

## 一、四视角排查清单

| 视角 | 下游开工时的核心痛点 | 通用排查要点（覆盖所有 CAD/平台级功能） |
|---|---|---|
| **研发** | **“我必须靠猜才能写代码”** | 1. **取值空间封闭性**：配置项、选项下拉、命令参数与枚举项是否全部闭合列出（严禁用“如”、“等”等开放式词汇截断合法值集合）；连续数值是否有默认值、上下限与量纲单位（视口物理像素 vs 图纸绝对单位）。<br>2. **前置与上下文边界**：前置条件、特殊/无效对象限制（锁定/冻结图层、不可见图元、外部参照）、历史兼容与数据生命周期。<br>3. **状态机与中断**：命令行或界面操作的中断与退出处理（ESC/取消/异常崩溃时的清理回滚）、撤销重做（Undo/Redo）边界。 |
| **品质 (QA)** | **“没有明确对错标准，我没法写用例”** | **场景 A（有输入源：快照/外部文档/本地资料/原型图）**：<br>- **溯源保真度（Lossless Check）**：对照原始输入源，原有实体、参数表、离散枚举和业务规则在新稿中是否被无意识丢弃或缩水？若是本期有意裁剪，是否在 Story Map 或非目标中显式声明。<br>**场景 B（无输入源：一句话诉求/全新孵化）**：<br>- **承诺闭环（Goal-to-AC）**：第 1 章承诺的业务目标与成功指标，在第 3 章功能与第 5 章验收（AC）中是否全量落实闭环，有无悬空承诺。<br>**通用质量底线（全场景适用）**：<br>- **行文客观与去营销化**：全文排查并消除夸张修饰语（如“极致”、“颠覆性”、“极其强大”）与模糊主观词；AC 的 Then 描述必须客观可量化判定（严禁“友好”、“适当”、“高效”等主观形容词）。<br>- **逆向与容灾测试**：空数据、异常字符、只读状态、极端超限等逆向反例是否有明确预期行为。 |
| **交互与设计** | **“操作走不通，界面图文打架”** | 1. **流程连贯性**：操作链路是否有断点，交互步骤与界面控件是否一一映射。<br>2. **图文一致性**：界面控件名称、文案与实际原型（若有）是否一致，严禁脑补操作路径。<br>3. **反馈明确性**：状态反馈、高亮提示、进度与错误提示文案是否明确。 |
| **产品化交付** | **“发布上线时漏了配套项”** | 1. **命令与入口**：命令英文名、别名、右键菜单与图标位置是否明确。<br>2. **系统资源与字典**：系统变量字典（第 6 章）、多语言资源依赖是否登记。<br>3. **帮助配套**：帮助文档入口与说明是否有依据。 |

## 二、消缺闭环机制（严禁记录不管）

排查发现断点时，必须就地闭环消缺，严禁只在 DEC 开放问题中堆砌清单后草草交付：

1. **Level 1：事实补齐型（直接闭环）**
   - **适用**：属于因提炼疏漏导致的定义、表格、离散枚举、单位或状态机缺失，且存在确定依据或遵循行业通用公约。
   - **动作**：直接在 PRD 正文中补齐缺失内容，重新运行静态检查（`validate_prd.py` 与 `validate_links.py`）。
2. **Level 2：业务决断型（交互闭环）**
   - **适用**：属于下游不可或缺但原始资料未定义、存在多种候选方案取舍的业务边界或规则分歧。
   - **动作**：立即在当前会话中向用户发起决策澄清（提出明确问题，给出推荐方案与依据），获取用户裁决后**当场将结论写入 PRD 正文**，彻底消灭断点；严禁不经沟通直接将下游痛点堆入 DEC 待确认项甩给研发。
3. **例外（明确延期）**
   - **适用**：用户明确裁决“本期不实现，明确延期”。
   - **动作**：在用户故事地图（Release 2/3）或非目标中明确记录延期范围，并在第 8 章 DEC 登记已决结论。

## 三、门禁通过与留痕

四视角排查无残留断点（或已完成交互闭环消缺）后，调用门禁脚本记录凭据：

```bash
python scripts/gate_state.py --workspace <工作区绝对路径> --clear review --evidence "<四视角审查结论与消缺事实>"
```

完成 `review` 门禁后，方可进入最终交付或发布 Confluence。
