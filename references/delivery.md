# 成稿与交付

仅在成稿、保存或检查交付结果时读取；讨论节奏与修改边界见入口。

## 整理与保存

完整稿按模板整理，删除模板填写提示、占位行和标题填写标记，保留实际未知、来源及历史记录；原需求中的合法代码或花括号不属于模板占位符。“编制”保留首版作者。新文档版本从 `0.1` 开始；已有文档沿用原格式，将末级数字递增一位并新增修订记录，文首文件版本与最新记录一致，不覆盖历史。使用个人 PAT 时先读取认证账号的中文名，修订人填写“`中文名+PrdRefiner`”；中文名不可读时写“`中文名待补充+PrdRefiner`”，不猜测或复用历史作者。非 PAT 场景按实际变更人填写。历史审核／批准记录注明所属版本，不沿用为当前批准。

默认在用户工作区根目录保存 `<需求名>.md`（名称未定用 `prd.md`）。首次优化另存以保留原稿；继续修改本任务输出稿时更新该稿，遇到不属于本任务的同名文件用新版本名。用户指定目录、文件或仅需片段时遵循指令。文件保存后回读核对；聊天正文和未导出的内部 Artifact 不算文件交付。

输出目录中默认只把 `<需求名>.md` 和实际发生产品澄清时的 `<需求名>_澄清决策记录.md` 作为用户需阅读的文档。PRD Refiner 生成的其他文件统一放入 `.assets/<需求名>/`：来源快照、下载或复制的图片、Mermaid 渲染图、转换中间稿、待提交与回读 Storage、差异文件、映射清单和校验结果等；正文用相对路径引用其中资源。不得把这些过程文件散落在输出目录或列作必读文档。用户原始资料保持原位；用户明确要求某项作为独立交付物或指定位置时按其要求。

优化已有稿时，在首次改动前保留原始正文；本地原稿未改动时可直接作基准。Confluence 来源使用图片规范定义的完整本地快照，写入前的并发核对另按平台规范进行。

Confluence 默认先保存并核对本地 Markdown 和图片，再写入；用户明确仅远程时省略本地稿。局部更新的本地完整稿按模板组织，并反映远端保留范围外内容后的完整结果；两种格式核对需求内容、版本和条目，章节布局可不同。本地稿不能反向转换后覆盖整页。

## 澄清记录与状态

编写或优化中实际向用户提出过产品澄清问题，交稿时另附 `<需求名>_澄清决策记录.md`，与主稿同目录并更新已有记录；用户明确不要时省略。记录问题与背景、实际候选及取舍、真实回答或未决、对应稿件版本及位置。答案改变时注明替代关系，先将最新决定写回 PRD，再由记录引用正文；不复制全部聊天或另写一套规则。图文冲突只有涉及产品决定时进入该记录。

讨论期间不要求每轮存文件。只检查、零提问或仅确认文件位置等操作信息时不要求澄清记录。仅远程交付时使用已授权的附件或记录页面；无此目标时在对话提供记录，不自动新建页面。

| 状态 | 使用条件 |
|---|---|
| 待补充工作稿 | 目标、范围或主要行为仍无法理解，保存已知与缺口 |
| 初版待核对 | 主要内容可理解，已知规则入文、未决显式，完成本轮检查，待产品核对 |
| 可供团队讨论的初版 | 满足“初版待核对”条件，且产品已认可当前版本用于讨论；可保留明确延期的产品问题和专业评估事项 |

按当前版本和实际核对情况标状态，不为交付文件额外索要认可；用户后续认可时再更新。脚本通过不升级产品状态；这些状态均不代表正式评审、研发批准或测试通过。文件、图片和平台显示是否齐备另行报告。

## 校验

完成内容规范中的复核，再对实际保存的本地 Markdown 执行（路径相对 Skill 根目录）：

```text
python scripts/validate_prd.py <稿件> --profile template
python scripts/validate_links.py <稿件> --format markdown --profile template
```

结构完整的稿件用 `template`，允许有明确未决；未完成工作稿用 `draft`；输入旧稿诊断用 `existing`。后两者放宽部分检查，不能据通过结果认定完整稿合格。脚本检查已支持的模板结构、编号、占位、图片路径及条目链接，不证明业务正确、图片可读或实际点击有效。仅交付片段时不运行全稿模板检查。

优化已有文稿时，结构及组合检查加 `--source <原始正文快照>`，支持 Markdown／HTML／Storage 文件，不接受页面 URL。源稿有图而输出零图会报错，数量减少会提示逐图核对；组合检查也比较 Markdown 与 Storage 的图片数量。按图片规范核对具体去向，数量相同不证明图片保留。用户明确只要纯文字时可省略源图数量检查，注明该选择。

脚本不能识别合理删图依据：有依据地移除全部源图时，保留原始报错并人工核对，不加回无关图片来换取通过。未提供源稿时只报告已做的输出图片检查。

正文使用图片时默认 `local`，文件须在 `.assets/<需求名>/images/` 中存在且可读，并由正文以有效相对路径引用；仅用户明确外链时使用 `--image-policy external`。仅目标阅读器确实无法跳转时，给引用检查加 `--reference-policy location`：接受内容规范中的“〔名称（编号）；位置：准确章节标题〕”，仍检查名称、唯一完整定义和章节归属，并披露未验证跳转。普通裸编号、错误链接或错误位置仍失败，不能为消除错误擅自降级。

Confluence 最终待提交和回读的 Storage 分别运行：

```text
python scripts/validate_delivery.py <Storage文件> --workspace <工作区根目录> --markdown <已保存Markdown>
```

组合检查包括 Markdown 结构／图片／引用、Storage 原生引用和目录骨架、两稿定义编号集合，以及每个 Mermaid 代码块对应的本地哈希 PNG 和 Confluence PNG 附件引用；浮动目录布局另检查 Storage 中不存在 `code`／`noformat` 宏，并保留白色不透明背景和 `z-index: 1000`。正文语义一致、实际渲染与授权范围 diff 另行核对。按实际条件使用例外参数：

- `--output-dir <目录>`：用户指定其他本地目录。
- `--remote-only` 并省略 `--markdown`：用户明确仅远程。
- `--layout inline`：用户明确正文目录。
- `--image-policy external`：用户明确外链图片。
- `--reference-policy location`：实际跳转能力受限，已标明章节位置与限制。

检查发现实际缺陷时先修复本次范围内的问题。局部修改对照改前、改后结果，范围外旧问题只报告，不为通过全稿检查擅自扩改。组合检查按完整模板和指定布局执行，不支持任意片段或旧页布局；合理删图、不同布局等不适用项逐项人工核对，保留原始检查结果并说明依据，不声称脚本全部通过。脚本无法运行或无法判定的部分如实标明，不把工具限制改写成产品缺陷。

最终提供已成功生成的文件／页面链接、必要变更和遗留项。按实际任务简述内容核对、静态校验、保存／写入及显示结果；部分失败说明具体缺项和已完成部分。无法保存时提供可复制正文，不虚报文件或页面。
