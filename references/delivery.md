# 成稿与交付

仅在成稿、保存或检查交付结果时读取。

## 1. 文件组织契约

严格划分人脑阅读资产与机器底层杂质，支持多会话解耦流转：

- **人看核心资产**（工作区根目录，支持跨会话纯净输入）：
  - **主稿（单文件）**：确认后直接产出 `<需求名>.md`（详细稿）；名称未定时用 `prd.md`。继续修改则更新同一文件并递增版本；首次优化已有稿时另存以保留原稿。目录直接写 `[TOC]` 标记，不手工维护各级标题链接。
  - **探讨结论**：`<需求名>_需求探讨.md`，按需沉淀候选、各自代价、被否理由与关键裁决——只记“为什么”。
  - **竞品分析**：`<需求名>_竞品分析.md`，按需沉淀先验外显、历史妥协与 CAD 三要素公约。
  - **澄清记录**：`<需求名>_澄清决策记录.md`，仅当实际向用户提出产品澄清且拍板时输出。
  - **帮助初稿**：`<需求名>_帮助初稿.md`，仅在用户要求由需求文档派生帮助内容时产出，不作为每次任务的固定产物。
- **解耦流转与子智能体起草**：成稿前必须将前序所有口头探讨、机制决断完整落盘至 `<需求名>_需求探讨.md` 与 `<需求名>_澄清决策记录.md`。宿主支持子智能体（Subagent）时，成稿阶段推荐派生独立子智能体仅读取上述落盘资产与模板进行主稿起草与静态校验（`validate_prd.py` / `validate_links.py`），以隔离长文本生成与工具调用杂音；起草完成后交回主会话，由主会话执行下游审查并直接与用户交互消缺。
- **底层机器资产**（`.assets/`，不打扰用户）：
  - 来源快照（`source.md`、`source.original.txt`、`manifest.json`、`images/`，见 [来源快照](snapshot.md)）、中间稿、下载原图、图表源文件、Mermaid 渲染图、校验报告、门禁凭据 `gates.json`（由 `gate_state.py` 维护）等直接放在此处；正文使用相对路径引用，不得散落在外。
  - **渲染图落点**：Mermaid 渲染图默认写入 `.assets/images/`（`render_mermaid.py --output-dir` 可改），与来源快照图片共用同一目录；文件名带内容哈希，不互相覆盖。
  - **正文只引可显示的图片**：位图与 SVG 可直接引用；业务流程图、架构图或文档源文件（如 draw.io 等）优先由宿主能力生成为图片（PNG/SVG）存入 `.assets/images/` 后以标准 Markdown 图片语法引用，源文件本身留在 `.assets/`，不写进正文。
  - 机器资产共用一个扁平目录，以快照的 `manifest.json` 为快照完成标记（其余资产各自独立）；换来源时用 `--force` 只覆盖快照自身的文件，不删除其他资产。
- 用户指定目录、文件名或仅需片段交付时，遵循用户指令。

## 2. 版本、作者与状态

- **版本**：新文档从 `0.1` 开始；已有文档递增末级数字并新增修订记录（如 0.1→0.2、V1.2→V1.3），文首版本与最新记录一致。首版“编制”人保持不变。
- **阶段与状态**：文档状态是唯一的阶段标识（待补充工作稿 → 初版待核对 → 可供团队讨论的初版），版本号只表示修订次数。成稿门禁判据见 [需求探索](brainstorm.md)。
- **修订人**：PAT 场景直接从快照元数据（`fetch_snapshot` 命令行输出的 `author.display_name`，或 `manifest.json` 的 `source.author.display_name`）读取认证账号中文名填写“`中文名+PrdRefiner`”（不可读时标“`中文名待补充+PrdRefiner`”，不猜测、不复用历史作者）；非 PAT 按实际变更人。
- **修订记录**：每次成稿新增一条，不覆盖历史；版本号按上文递增；文首“审核／批准”填写当前版本的真实记录，未审核、未批准留空。
- **密级**：按依据勾选，未知注明，不猜测。
- **文档状态**（三选一）：

| 状态 | 适用条件 |
|---|---|
| **待补充工作稿** | 核心目标、范围或主要行为缺失，仅记录已知与缺口 |
| **初版待核对** | 规则可理解、未决已显式标出，完成本轮检查，待产品核对 |
| **可供团队讨论的初版** | 满足初版条件，且产品明确认可用于讨论 |

## 3. 本地交付校验

完整本地 Markdown 保存后，必须执行静态检查与下游审查：

1. **静态检查**：

```bash
python scripts/validate_prd.py <稿件绝对路径> --profile template
python scripts/validate_links.py <稿件绝对路径> --format markdown --profile template
```

| 场景 | 对应参数 | 说明 |
|---|---|---|
| **优化已有稿** | `--source <原始文档>`（`validate_prd.py`） | 检查模板结构与图片保留情况 |
| **未完成中间稿 / 旧稿诊断** | `--profile draft` / `existing` | `draft` 仅用于刻意保留缺口的中间稿；`existing` 只用于输入稿件诊断，不用于本次产出 |
| **外部图片** | `--image-policy external` | 仅在用户明确要求外链时使用 |
| **无跳转支持环境** | `--reference-policy location` | 仅在目标阅读器不支持锚点时使用 |

2. **下游审查与消缺（review 门禁）**：
   静态检查通过后，必须对照 [下游审查清单](downstream-review.md) 完成研发、品质、交互与产品化四视角闭合排查。排查发现断点时，依级别执行事实补齐（直接修改稿件）或业务决断（交互澄清并写入稿件）完成就地消缺；随后记录门禁凭据：

```bash
python scripts/gate_state.py --workspace <工作区绝对路径> --clear review --evidence "<消缺事实与审查结论>"
```

- 检查发现的缺陷属于本次修改范围的必须直接修复；超出本次范围的旧问题仅作报告，不擅自扩改。
- 片段交付任务不运行全稿模板检查。写入 Confluence 时的平台校验见 [平台写入](publish-confluence.md)。

## 4. 帮助初稿交付

由需求文档派生帮助内容时读取。

- **单一源**：帮助内容只维护 `<需求名>_帮助初稿.md` 一份，含主题结构、界面截图清单、界面术语对照与待补译项；不得并行维护内容相同的 Markdown 与 HTML 两套稿。
- **格式依据**：主题形态与样式只能取自用户提供的当期帮助模板或随 skill 的样例 `assets/help/help-demo/`；没有明确依据时只出 Markdown 框架（依据 [帮助初稿模板](../assets/help-template.md)）。生成 HTML 骨架后即以其为唯一修改对象，不再回写 Markdown。
- **图位**：只登记图名、类型、建议内容与图注，不生成或引用图片文件，也不写成图片语法。
- **术语**：界面串译法只能取自用户提供的字典（`scripts/lookup_term.py` 按 `assets/help/multilanguage-mapping.txt` 查表），逐条标注命中、未命中或待补译；不得自行翻译。
- **边界**：不得据此声称已产出正式帮助文档、已完成多语言版本或已补齐截图。
