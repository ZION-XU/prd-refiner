# 成稿与交付

仅在成稿、保存或检查交付结果时读取。

## 1. 文件组织契约

严格划分人脑阅读资产与机器底层杂质，支持多会话解耦流转：

- **人看核心资产**（工作区根目录，支持跨会话纯净输入）：
  - **主稿**：`<需求名>.md`（名称未定用 `prd.md`）。首次优化另存以保留原稿，继续修改则更新该稿。
  - **探讨结论**：`<需求名>_需求探讨.md`，按需沉淀痛点本质、JTBD 与关键裁决备忘。
  - **竞品分析**：`<需求名>_竞品分析.md`，按需沉淀先验外显、历史妥协与 CAD 三要素公约。
  - **澄清记录**：`<需求名>_澄清决策记录.md`，仅当实际向用户提出产品澄清且拍板时输出。
- **底层机器资产**（`.assets/`，不打扰用户）：
  - 来源快照（`source.md`、`manifest.json`、`images/`）、中间稿、下载原图、Mermaid 渲染图、校验报告等直接放在此处，不建需求名子目录；正文使用相对路径引用，不得散落在外。
  - 机器资产共用一个扁平目录，以快照的 `manifest.json` 为完成标记；换来源时用 `--force` 只覆盖快照自身的文件，不删除其他资产。
- 用户指定目录、文件名或仅需片段交付时，遵循用户指令。

## 2. 版本、作者与状态

- **版本**：新文档从 `0.1` 开始；已有文档递增末级数字并新增修订记录，文首版本与最新记录一致。首版“编制”人保持不变。
- **修订人**：PAT 场景直接从快照元数据（`fetch_snapshot` 命令行输出或 `manifest.json` 中的 `author.display_name`）读取认证账号中文名填写“`中文名+PrdRefiner`”（不可读时标“`中文名待补充+PrdRefiner`”）；非 PAT 按实际变更人。
- **文档状态**（三选一）：

| 状态 | 适用条件 |
|---|---|
| **待补充工作稿** | 核心目标、范围或主要行为缺失，仅记录已知与缺口 |
| **初版待核对** | 规则可理解、未决已显式标出，完成本轮检查，待产品核对 |
| **可供团队讨论的初版** | 满足初版条件，且产品明确认可用于讨论 |

## 3. 本地交付校验

完整本地 Markdown 保存后，必须执行静态检查：

```bash
python scripts/validate_prd.py <稿件> --profile template
python scripts/validate_links.py <稿件> --format markdown --profile template
```

| 场景 | 对应参数 | 说明 |
|---|---|---|
| **优化已有稿** | `--source <原始快照>` | 检查模板结构与图片保留情况 |
| **工作稿 / 旧稿诊断** | `--profile draft` / `existing` | 仅在非完整成稿场景放宽校验 |
| **外部图片** | `--image-policy external` | 仅在用户明确要求外链时使用 |
| **无跳转支持环境** | `--reference-policy location` | 仅在目标阅读器不支持锚点时使用 |

- 检查发现的缺陷属于本次修改范围的必须直接修复；超出本次范围的旧问题仅作报告，不擅自扩改。
- 片段交付任务不运行全稿模板检查。写入 Confluence 时的平台校验见 [平台写入](publish-confluence.md)。
