# 内容约定

规定 PRD 正文的信息密度要求、CAD 领域常见考虑点、章节结构与编号引用规范。本文件是 **PRD 正文内容规范的唯一来源**：[模板](../assets/prd-template.md)提供章节骨架与填写提示；目录组织、合龙与文件状态见 [成稿与交付](delivery.md)。

## 1. 图文分工与高信息密度原则

- **原型与正文分工明确**：原型图与 HTML 附件负责展示“界面长什么样（视觉布局、常规控件外观、尺寸排布）”；PRD 正文只写**“光看静态画面看不出来的特殊逻辑与底层规则”**（数据来源、默认记忆、特殊取值边界、校验恢复、跨控件联动、内核持久契约与异常回滚）。
- **单功能内四块内容各司其职**：在每个功能（`FR-xxx`）内部，信息按四个部分归位，同一条规则只在一个地方写清楚，不来回抄写：
  1. **入口与命令契约** → 写命令名、别名、菜单位置与 `-CMD` 命令行提示流；
  2. **交互卡重点控件与状态说明** → 只写有特殊逻辑、复杂联动、非自明校验或本次发生改动的重点控件（原型里一眼能看懂的常规控件不用逐个罗列）；
  3. **CAD 内核与环境边界（`BR-xxx`）** → 写跨控件的几何算法、DWG/DXF 图元数据契约、特殊图层/块/UCS 环境边界、ESC 回滚与 Undo 事务；
  4. **验收标准（`AC-xxx`）** → 写具体测试输入（Given/When）与可量化的结果判定标准（Then）。
- **确认状态与追溯**：有明确依据的要求引用 `SRC-xxx` 来源；尚存分歧或待定指标的事项统一归入第 6 章 `DEC-xxx` 开放问题，写明备选方案与取舍代价。

## 2. ZWCAD 领域常见考虑点（CAD 防漏清单）

设计每个功能（FR）的原型与规格时，按需检查以下 CAD 工程细节是否已经考虑清楚：

- **图元与几何处理**：明确对象身份（Handle/ObjectId）、图层与颜色/线型/线宽继承（ByLayer/ByBlock）、单位制、坐标系（WCS/UCS 转换）、浮点容差、精度，以及遇到退化图形（零长度、自相交、极小面积）时怎么保底或报错。
- **CAD 三项基本约定**：
  1. **命令入口**：命令英文名、别名（PGP）、Ribbon/经典菜单位置、右键菜单、是否支持先选对象再执行命令（Noun-Verb）及无弹窗命令行模式（`-CMD`）；
  2. **系统变量**：关联的系统变量名、数据类型、默认值、合法取值范围及保存位置（DWG 图纸内／注册表／仅当前会话）；
  3. **特殊图纸环境**：遇到锁定／冻结／关闭图层上的图元怎么处理、块编辑器（BEDIT）内能否使用、外部参照（Xref）与动态块怎么处理、多文档切换（MDI）时状态如何隔离。
- **命令行提示与取消/撤销**：
  - 写清命令行的提示顺序、关键字选项、默认回车行为与输入错误提示；
  - 明确操作中途按 `ESC` 键或点取消时，界面怎么恢复、画布上的临时预览线怎么清理、数据怎么回滚，以及按 `Ctrl+Z`（Undo）时哪几步算作一次撤销。
- **取值范围写完整**：下拉框选项、参数范围写完整（数值写明最小值、最大值、步长、默认值和单位；下拉选项把所有可选项列全）。
- **表达清晰可测**：
  - 比较符号直接用清晰符号（≥、≤、≠、±、→、× 或 >=、<=、->）；
  - 用具体可测的数字和结果描述要求（如毫秒数、图元属性值、状态变化结果），不用“体验友好”、“响应迅速”等模糊形容词。

## 3. 编号与引用约定

- **条目编号**：按类型稳定编号（FR 功能、BR 规则、AC 验收、NFR 非功能、DEC 决定／开放问题、RK 独立风险、SRC 来源）；帧 ID 使用 `FR-001-S1`。移动内容不重新编号，废弃编号保留记录且不复用。
- **同页锚点引用**：规则（`BR`）与验收（`AC`）在各自表格第一列内嵌锚点 `<a id="br-001"></a>`，跨处提及采用 `[条目名称（编号）](#锚点)` 引用。

---

## 4. 章节结构与流程图

- **核心章节**：完整 PRD 包含第 1~3、6、7 章为核心章节（1. 背景、用户与目标，2. 范围与边界，3. 功能与交互规格，6. 风险与开放问题，7. 来源与参考资料）；第 4 章（数据、系统变量与接口）和第 5 章（性能与非功能要求）按需保留。出稿时清除模板占位符。
- **业务总体流程（第 1.3 节）**：使用简洁的 **Mermaid 流程图（Flowchart）** 表达核心业务主干（通过 `scripts/render_mermaid.py` 渲染为 `.assets/images/` 下的本地 PNG 引用），或用结构化步骤（输入 → 处理 → 结果）写清。

## 5. 交互规格检查点

第 3 章每个 FR 的交互卡须满足以下要求（写法见 [交互与原型设计](interaction-design.md)）：

- **状态图与重点控件逻辑清晰**：有界面的功能嵌入 `FR-xxx-Sx` 状态截图，并针对重点控件或改动点写清数据源、取值校验与联动逻辑（原型里一眼能看懂的常规控件直接看图即可）；纯命令行交互使用状态事件表；无交互后台功能写明 `交互卡：未涉及（具体理由）`。
- **文档与原型一致**：正文中重点控件的默认值、选项与联动关系和 `prototype.html` 保持一致。
- **验收标准有覆盖**：关键的状态变化、边界校验与异常取消都有对应的 `AC-xxx` 验收用例。
