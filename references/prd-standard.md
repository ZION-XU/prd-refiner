# 内容约定

规定来源状态、团队业务边界、表达约定、编号引用与成稿完备，防止主观臆断与内容缺失。本文件是 **PRD 正文内容规范的唯一来源**：PRD 正文中有关“必须／不得／依据／取舍／顺序”的要求集中在此；[模板](../assets/prd-template.md)只提供骨架、字段取值域与描述性填写提示；文件、版本、密级与文档状态见 [成稿与交付](delivery.md)。

职责不交叉：`SKILL.md` 规定调用门禁、快照和范围等工作流约束，本文件规定 PRD 正文内容，[成稿与交付](delivery.md)规定交付形态。对同一事项有冲突时，按用户明确指令、`SKILL.md` 硬约束、对应领域规范、模板提示的顺序处理。

## 1. 依据、状态与内容所有权

模板各字段用于对照完整性，不代表内容已确定；未知事项就地标明并登记第 8 章 DEC，不为填满格式捏造要求或负责人。

- **内容所有权**：业务事实只能来自用户输入或用户提供的资料——用户与角色、背景与现状痛点、目标与成功判据、范围与非目标、业务规则、优先级与数值。AI 不自行生成这类内容，只负责结构化、推导与格式化（编号、GWT 形式、表格与图示形式、措辞精简，以及由已给资料做不新增信息的推导）。
- **确认状态与追溯**：条目确认状态仅区分“已确定”与“待确认”两类：
  - **已确定**：有明确依据的要求。业务事实须有用户确认，技术事实须有版本化依据；FR、BR、NFR 与已决定的 DEC 须直接引用 SRC 来源；
  - **待确认**：凡未经确认的推测、分歧或未知项，一律列入第 8 章 DEC 开放问题，严禁假装确定。
- **数值与指标**：已确认数值须保留依据来源；无依据时不编造阈值，待定指标直接列入 DEC。
- **AI 推导边界**：由已确认事实重解出的候选机制，在提出时须向用户说明推导依据，经用户裁决后方可进入正文；未决前仅作 DEC 备选。

## 2. 团队与 CAD 特有边界

- **CAD 实体与几何语义**：涉及对象身份、图层/属性、关联、单位、坐标、容差、精度、生命周期或退化/无解/多解时，必须写明具体语义，不凭“CAD 通常如此”推测默认值。
- **三要素公约抗排异**：功能改变或暴露命令、系统变量、特殊图层或复杂图元行为时，必须核查适用的行业公约以降低迁移成本。核查维度为：①命令英文名/别名/右键菜单；②系统变量命名、默认值与作用域（图纸级／注册表级／会话级）；③特殊图层（冻结/关闭/锁定）与复杂图元（Xref/动态块）边界惯例。不适用维度标“未涉及”并说明原因；调整或例外须说明理由并记录 DEC。
- **CAD 命令行提示流与状态机**：经 CAD 命令启动或暴露命令行提示的功能，必须定义最小闭环：入口及初始状态、提示与输入、执行反馈、异常反馈、ESC 后的结果与恢复状态。纯图形界面功能不强制命令行提示流；若交互可取消，仍须定义取消后的可见状态。
- **取值空间封闭**：凡暴露给用户的配置项、选项下拉、命令参数或样式字典，必须完整列出其取值空间（连续数值标明范围、步长、默认值与量纲单位；离散项必须完整枚举，严禁用举例词概括开放集合）。
- **符号与数学排版**：常规逻辑判断、比较关系与流程指向必须使用原生 Unicode 符号（如 ≥、≤、≠、±、→、×）或程序符号（>=、<=、->），严禁使用 LaTeX 语法（如 $\ge$、$\to$）包裹常规符号；仅涉及复杂空间几何微积分等真数学公式时方可使用独立公式块。
- **语义质量三原则**：
  - 验收客观可测：可执行 AC 的 Given 必须包含可构造的具体样本数据，When 为明确操作或事件，Then 包含客观判定真值；
  - 严禁假设偷渡：未获用户确认的推测不得写为确定要求（登记方式见 §1 确认状态与追溯）；
  - 业务与实现解耦：只约束外部可见业务行为、兼容性和合规所需的技术契约；不指定可替换的底层算法或私有数据结构。
- **未完成验收**：未知输入、行为或真值时，必须登记 DEC；AC 可说明已知部分并标明“非可执行（DEC-xxx）”，不得作为验收完成或通过依据。
- **复杂度控制**：简单只读功能指不改写持久化数据且不触发外部副作用的查询或展示；除非已有依据，不凭空增加权限、并发或撤销等设计。已核实存在的权限、并发或副作用仍须如实说明。
- **工业工程文风与客观表述**：PRD 是研发与品质开工的工程契约，文风必须严谨、中立、克制；直述行为、状态与逻辑，禁止带有宣传感或推销色彩的叙事。严禁出现互联网/营销类夸张修饰语（如“极致体验”、“颠覆性”、“前所未有”、“惊艳”、“极其强大”、“秒级响应”等空泛浮夸字眼）；禁止使用“操作简单友好”、“界面美观”、“性能卓越”等主观形容词作为需求或判据，必须转译为具体操作步骤、界面显隐/可用状态机、或客观可量化的参数指标。

## 3. 编号与引用约定

- **条目编号**：按类型稳定编号（FR 功能、BR 规则、AC 验收、NFR 非功能、DEC 决定／开放问题、RK 独立风险、SRC 来源）；移动内容不重新编号，废弃编号保留历史记录且不得复用。
- **单一定义**：一项规则仅有一处完整定义，严禁跨章节或跨表格/小节重复声明。规则（BR）与验收（AC）默认在表格第一列内嵌锚点 `<a id="..."></a>` 完整闭环；仅当单条规则分支极度复杂时，表格才作索引清单、正文另立小节承载完整正文。
- **规范引用**：引用采用 `[条目名称（编号）](#锚点)`；跨章节引用保留当前语境概述；Confluence 使用原生锚点，见 [平台写入](publish-confluence.md)。

## 4. 章节完备与成稿规范

规范与骨架的分界：**模板只回答“这个格子写什么”，本文件回答“应当写成什么样、必须怎样、不得怎样”**——用于防范内容缺失或写得不达标；纯描述字段内容范围的句子留在模板。

- **章节取舍**：第 1~5、8、9 章为核心章节，必须保留；其余章节与小节适用时填写，明确无关时省略，适用但未知时说明缺口；可按内容增加字段。出稿删除模板的填写提示，保留实际状态与讨论点。
- **定义位置**：FR 在完整功能标题处定义，功能清单只作索引；规则与验收的单一定义与锚点规则见 §3。
- **验收可执行**：输入明确到可选取或可构造；未定行为注明缺口；测试执行方案留待品质／研发评估，不填写执行记录。
- **独立风险与开放问题**：影响方案取舍的未决事项统一登记为 DEC；独立风险用 RK 编号记录触发、影响与应对，不与同一 DEC 重复登记。
- **术语与跨文档引用**：术语首次出现即解释，较多时增术语表；跨文档引用注明文档名称、版本和位置。
- **流程表达与分级自适应（第 1.3 节）**：
  - **中大型与多阶段复杂需求**：推荐采用 **二维用户故事地图（2D User Story Map）**。横向为端到端主干用户活动（Backbone），纵向按优先级/价值切片组织发布泳道（如 MVP、Next、Future），每个卡片标明故事编号与对应的 FR 索引。准备结构化 JSON（字段契约见 [故事地图结构](../assets/story-map-schema.md)），用 `scripts/render_story_map_vector.py` 出 SVG 或 PNG（`--scale` 可调，默认 2；图片显式落 `.assets/images/`，与 Mermaid 图同目录），需要人工精修时先用 `scripts/story_map_to_excalidraw.py` 生成可编辑场景。正文以标准 Markdown 相对路径引用。直观呈现全局主线、功能归属与版本切片。
  - **简单与单向流程需求**：严禁形式主义与过度设计。对于单点功能、轻量改动或单向顺序交互，直接使用轻量流程图（宿主制图或 Mermaid 渲染 PNG 引用）或清晰的结构化文本步骤（输入 → 处理 → 结果）表达，快速闭环。
  - **图示资产落盘公约**：无论是流程图还是故事地图，均须作为本地静态图片资产落盘至 `.assets/images/`，正文统一使用标准 Markdown 图片语法引用；严禁在正文依赖不可控的第三方远程制图服务或特殊平台宏，使 Confluence 发布与本地离线浏览不依赖外部服务。
  - **渲染环境不可用时的降级**：`render_mermaid.py` 与故事地图的 PNG 渲染（`render_story_map_vector.py` 的 PNG 模式）依赖本机无头浏览器，SVG 输出不需要。无可用浏览器或渲染失败时，改用结构化文本步骤（输入 → 处理 → 结果）或宿主已渲染的静态图片表达，并如实说明未出图；不得留下指向不存在图片的引用，也不得把渲染脚本的失败报告当作已交付图。
- **不虚构状态**：优先级、目标版本、交付切片不虚构，未排序或未决定即注明，不写成排除项。
