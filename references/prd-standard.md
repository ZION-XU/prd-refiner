# PRD 初版内容标准

本文件供 Skill 检查内容质量；唯一的 [PRD 模板](../assets/prd-template.md)维护章节、字段和简短填写提示，[工作流](workflow.md)说明交互和修改。字段清单与章节取舍直接查模板，不在此另列一套。

## 初版与责任

初版使读者理解目标、范围、主要行为和需要继续讨论的事项。它不是审核版或可直接执行的工程承诺。产品核对、正式评审、研发完成与测试通过是不同状态。

已明确行为应有可判断结果；未知行为先记录缺口及影响，不为了填验收表编造规则。未决项可带入团队讨论；目标和主要行为尚无法理解的稿件标为待补充工作稿。

## 信息状态与依据

| 内容 | 处理 |
|---|---|
| 用户明确要求、目标原稿中的有效要求或明确适用本期的资料 | 写入对应正文，保留必要来源与版本；不能因缺少外部佐证删除原稿要求 |
| 外部参考、竞品资料、仅作背景的历史稿 | 按原名称引用，不默认继承为本期要求；先辨明资料用途 |
| 原型观察 | 只证明实际可见内容；业务语义参见原型规范 |
| AI 暂定／建议 | 可提出具体方案作为初版讨论起点，注明理由、适用前提及待确认部分；未被采纳前不写成已决定行为 |
| 冲突或未知 | 就地标明问题和影响，必要时关联开放问题 |
| 共同评估 | 标明建议参与角色、需共同决定的具体问题及影响；不要求产品先完成技术评估，也不声称相关人员已参与 |
| 不适用 | 可删除相应按需内容；不把未知当成不适用 |

保留来源名称与链接，仅在用户明确要求时脱敏。脱敏时保留可理解的代称及出处关系；不把“竞品”二字或具体商标视为自动禁止词。

确定性与讨论分工分别表达：内容可为“已确定（注明依据）”“AI 暂定（待确认）”或“待确认（尚无方案）”；另说明由产品核对、研发评估、品质评估，还是需相关角色共同讨论。提问与记录的分流遵循 [澄清方法](clarify.md)，不把专业评估转成产品必答题。建议参与角色不等于已分配负责人。影响范围或主要行为的未决项关联 DEC，同类细节可合并，不为每个字段创建问题。

字段、数据结构、接口或算法等具体建议可以写入对应章节，以帮助讨论；按条目或同一状态的整组内容标明“AI 暂定，需研发评估”，并说明哪些业务含义已确定、哪些技术细节待讨论。只有部分内容确认时分别标注，不能用整章“已确定”覆盖尚未确认的细节。AI 暂定方案不自动成为本期范围或正式验收承诺。

## 表达与检查

模板说明信息放在哪里，下列标准判断已经写出的内容是否有用；有对应字段不等于已经满足标准。检查动作、十二个覆盖方面和角色视角见 [内容检查](review.md)，不复制为另一套填写清单。

| 标准 | 判断依据 |
|---|---|
| 必要且符合目标 | 功能回应实际用户任务；范围、例子和候选方案没有被无依据扩成承诺 |
| 清楚 | 主体、对象、条件、动作与结果含义确定；同一术语稳定，避免会改变结果的多种解释 |
| 在本期场景内完整 | 读者能走通主要任务及实际相关分支；依赖、例外与保持项足以理解，未知显式；不追求全部想象场景 |
| 一致 | 条件、数值、状态与结论不冲突；正文、验收、可读原型遵循同一决定 |
| 可验证 | 已明确行为能形成可观察结果，判断所需场景和依据可说明；没有测量依据的指标保持未决 |
| 有依据、可追溯 | 关键结论能够定位到适用资料或明确决定；引用确实支持该结论，观察、推断与已采纳决定可区分 |
| 简洁可维护 | 一项规则只定义一次，流程与验收引用；合并重复而保留条件和例外，不为每句话建表或编号 |

对既有能力说明本次变化及相关保持项，不要求补全全部历史资料。图文核对读取边界见原型规范；角色视角不表示这些人员实际审核过。

## 统一框架与编号

使用模板对应字段的编号类型，不为每句建立编号。

新编、润色、深化或局部修改后的 PRD 均使用当前模板框架。旧稿作为输入，将有效内容映射到相应章节，缺失内容明确标记；按需章节依模板规则取舍，不为了补齐框架编造需求。仅检查时对照模板报告差异，不改稿。

按模板规定的位置定义编号。兼容模板且唯一的编号保持稳定；原编号缺失、不兼容或冲突时，分配相应编号，并在相关条目或简短修改说明中保留旧编号／原章节与新位置的对应关系，同步更新引用。结构移动不能改变产品含义，检查工具不能完整理解任意格式，应披露范围。

历史稿的 `DATA-xxx` 可按含义转为数据规则 `BR-xxx`，`CL-xxx` 的决定／未决项转为 `DEC-xxx`，来源按模板使用 `SRC-xxx`。先辨认内容再转换，不机械替换全部字符串；保留旧编号对应，不把旧编号体系带入模板作为新增要求，也不复用编号表达不同含义。

`prd.md` 或用户选择的其他文件名，是本轮主要文稿。源稿、旧版本与同目录其他文件不自动视为冲突，也不应被删掉。过程附件可选，不要求附件 README 或独立追溯体系，更不能另定义一套业务规则。

## 检查的边界

所有新编或优化的完整初版使用 `validate_prd.py --profile template`；按模板组织的未完成工作稿使用 `draft`；`existing` 仅用于输入旧稿的只读诊断，不作为输出稿符合模板的依据。脚本只查可解析结构、引用、已知模板占位及本地图片存在性，既不判断专业规则正确，也不证明已覆盖全部验收。

脚本错误需修复或准确报告；提示不能当成要求用户继续作答的硬门槛。允许先保存可用工作稿。未经产品核对只能标为工作稿或初版待核对；已有文档的历史评审记录按来源保留，本轮修改不能沿用为新版本的批准结论。
