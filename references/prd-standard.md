# 内容约定

规定主体视角、信息密度准则、CAD 领域防漏清单、内聚结构与表达规范。本文件是 **PRD 正文内容规范的唯一来源**：[模板](../assets/prd-template.md)提供章节骨架与字段提示；分片目录、合龙与文件状态见 [成稿与交付](delivery.md)。

## 1. 工程主体视角与高信息密度准则

### 1.1 纯粹的 CAD 工程主体视角
- **三大合法工程主语**：PRD 正文面向研发与品质（QA）定义软件行为契约，所有句子围绕三类实体展开：
  1. **`CAD 终端设计师`**：在软件中执行制图、建模、配置操作的终端用户；
  2. **`ZWCAD 系统`**：响应输入、执行几何计算、渲染视口反馈与管理状态机的软件本体；
  3. **`图纸／图元／系统变量`**：承载几何属性、样式字典与持久化数据的业务实体。
- **单一数据源提炼**：正文规格只从定稿的本地交互原型（`prototype.html`）与产品经理（PM）确认的 CAD 业务事实中提取。

### 1.2 图文分工与高信息密度（不写重复废话）
- **原型与正文分工明确**：原型图与 HTML 附件负责展示“界面长什么样（视觉布局、常规控件外观、尺寸排布）”；PRD 正文只写**“光看静态画面看不出来的特殊逻辑与底层规则”**（数据来源、默认记忆、特殊取值边界、校验恢复、跨控件联动、内核持久契约与异常回滚）。
- **单功能内四块内容各司其职**：在每个功能（`FR-xxx`）内部，信息按四个部分归位，同一条规则只在一个地方写清楚，不来回抄写：
  1. **入口与命令契约** → 写命令名、别名、菜单位置与 `-CMD` 命令行提示流；
  2. **交互卡重点控件与状态说明** → 只写有特殊逻辑、复杂联动、非自明校验或本次发生改动的重点控件（原型里一眼能看懂的常规控件不用逐个罗列）；
  3. **CAD 内核与环境边界（`BR-xxx`）** → 写跨控件的几何算法、DWG/DXF 图元数据契约、特殊图层/块/UCS 环境边界、ESC 回滚与 Undo 事务；
  4. **验收标准（`AC-xxx`）** → 写具体测试输入（Given/When）与可量化的结果判定标准（Then）。

### 1.3 确认状态与追溯
- **已确定**：有明确依据的要求（引用 `SRC-xxx` 来源）；
- **待确认**：尚存分歧或待定指标的事项，统一归入第 6 章 `DEC-xxx` 开放问题，写明备选方案与取舍代价。

## 2. ZWCAD 领域防漏检查单（CAD 特有边界）

设计每个功能（FR）的原型与规格时，逐项核查并落实以下 CAD 工程要素：

- **CAD 实体与几何语义**：明确对象身份（Handle/ObjectId）、图层与颜色/线型/线宽继承（ByLayer/ByBlock）、单位制、坐标系（WCS/UCS 矩阵转换）、浮点容差、精度及退化几何（零长度、自相交、极小面积）的保底生成或拦截语义。
- **三要素公约核查**：
  1. **命令入口**：命令英文名、别名（PGP）、Ribbon/经典菜单位置、右键菜单、是否支持先选后执行（Noun-Verb）及命令行静默模式（`-CMD`）；
  2. **系统变量**：变量名、数据类型、默认值、合法域及保存作用域（DWG 图纸级／注册表级／会话级）；
  3. **图元与环境边界**：锁定／冻结／关闭图层上的图元处理、块编辑器（BEDIT）内部可用性、外部参照（Xref）与动态块边界、多文档切换（MDI）状态隔离。
- **命令行提示流与 ESC/Undo 状态机**：
  - 定义命令行的完整状态循环：初始提示、关键字列表、默认值括弧显示、异常输入回显；
  - 明确任意步骤按 `ESC` 键或取消时的界面恢复状态、临时橡皮筋/虚影销毁与数据回滚范围，以及 `Undo/Redo` 的原子事务分组。
- **取值空间封闭**：所有配置项、下拉枚举、命令参数均给出完整闭集（连续数值写明上下限、步长、默认值与量纲单位；离散枚举完整列出全部合法项）。
- **精确工程表达**：
  - 逻辑与比较关系使用原生 Unicode 符号（≥、≤、≠、±、→、×）或程序符号（>=、<=、->）；
  - 全文使用可观测、可测量的工程指标（如具体毫秒数、帧率、图元属性真值、状态迁移结果）及中立的行业工程术语。

## 3. 编号与引用约定

- **条目编号**：按类型稳定编号（FR 功能、BR 规则、AC 验收、NFR 非功能、DEC 决定／开放问题、RK 独立风险、SRC 来源）；帧 ID 使用 `FR-001-S1`。移动内容不重新编号，废弃编号保留记录且不复用。
- **同页锚点引用**：规则（`BR`）与验收（`AC`）在各自表格第一列内嵌锚点 `<a id="br-001"></a>`，跨处提及采用 `[条目名称（编号）](#锚点)` 引用。

## 4. 章节完备与流程图规范

- **核心章节**：完整 PRD 包含第 1~3、6、7 章为核心章节（1. 背景、用户与目标，2. 范围与边界，3. 功能与交互规格，6. 风险与开放问题，7. 来源与参考资料）；第 4 章（数据、系统变量与接口）和第 5 章（性能与非功能要求）按需保留。出稿时清除模板占位符。
- **业务总体流程（第 1.3 节）**：使用紧凑的 **Mermaid 流程图（Flowchart）** 表达核心业务主干（通过 `scripts/render_mermaid.py` 渲染为 `.assets/images/` 下的本地 PNG 引用），或使用结构化步骤（输入 → 处理 → 结果）。

## 5. 交互规格完备性

第 3 章每个 FR 的交互卡须满足以下判据（构建与提炼方法见 [交互与原型设计](interaction-design.md)）：

- **状态图与重点控件逻辑闭环**：包含界面的功能嵌入 `FR-xxx-Sx` 状态帧图，并针对重点控件或增量改动点给出数据源、取值校验与联动逻辑（原型自明的常规控件直接见原型）；纯命令行交互使用状态事件表；无交互后台功能写明 `交互卡：未涉及（具体理由）`。
- **数据与原型同源**：正文中各控件的默认值、枚举项与联动关系与 `prototype.html` 保持同源一致。
- **验收全覆盖**：关键状态迁移、边界校验与异常回滚均有对应的 `AC-xxx` 验收用例覆盖。
