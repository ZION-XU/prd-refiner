# 内容约定

规定主体边界、来源状态、CAD 领域防漏准则、内聚结构与表达规范。本文件是 **PRD 正文内容规范的唯一来源**：[模板](../assets/prd-template.md)只提供骨架与字段提示；分片目录、合龙与文件状态见 [成稿与交付](delivery.md)。

## 1. 本体边界、元话语隔离与来源状态

### 1.1 双重主体解耦与元话语物理隔离（最高红线）
- **严格区分两类主体**：
  - **产品经理（PM / 需求发起人）**：在对话窗口中向 AI 下达指令、讨论工作方法、审阅 HTML 原型的操作者；
  - **CAD 终端用户（设计师 / 工程师 / 绘图员）**：使用 ZWCAD 软件进行制图与建模的真实软件受众。
- **元话语零容忍**：PRD 正文是面向研发与测试的工程规格合同，正文句子的核心主语只能是 **`CAD 终端设计师`**、**`ZWCAD 系统`** 或 **`图纸/图元/数据`**。PM 与 AI 在对话过程中的协作策略、测试安排、会话调度（如“采用影子伴跑策略”、“先测试一下 Skill”、“分步切片推进”等）均属**人机协作元话语**，严禁以任何形式混入 PRD 任何章节。
- **以 HTML 原型与确认事实为唯一数据源**：功能细节只能提取自定稿的本地 `prototype.html`（`<cad-*>` 组件树）及 PM 明确拍板的 CAD 业务事实，绝不从多轮闲聊记录中摘要凑字。

### 1.2 确认状态与追溯
- **内容所有权**：业务痛点、目标范围、业务规则与优先级只能来自 PM 确认或输入资料；AI 只负责基于 `<cad-*>` 组件库构建原型、按 CAD 清单追问补漏及结构化提炼，不为填满模板捏造要求。
- **二元确认状态**：
  - **已确定**：有明确依据的要求（引用 `SRC-xxx` 来源）；
  - **待确认**：未经确认的推测、分歧或待定指标，一律登记至第 6 章 `DEC-xxx` 开放问题，严禁假装确定写入正文。

## 2. ZWCAD 领域防漏检查单（CAD 特有边界）

陪伴 PM 设计每个功能（FR）的原型与规格时，AI 必须自动核查以下 CAD 领域暗礁：

- **CAD 实体与几何语义**：涉及对象身份、图层/属性、关联、单位、坐标（WCS/UCS）、容差、精度、生命周期或退化/无解/多解时，写明具体处理语义，不凭“通常如此”默认略过。
- **三要素公约抗排异**：功能改变或暴露命令、系统变量、特殊图层或复杂图元行为时，核查三项行业公约以降低设计师迁移成本：
  1. **命令入口**：命令英文名、命令别名（PGP）、Ribbon/经典菜单位置、右键菜单与命令行静默模式（`-CMD`）；
  2. **系统变量**：变量命名、数据类型、默认值、取值范围及保存作用域（图纸级 DWG／注册表级／会话级）；
  3. **图元与环境边界**：特殊图层（锁定／冻结／关闭）上的图元处理、块编辑器（BEDIT）内部表现、外部参照（Xref）与动态块边界、多文档切换（MDI）状态保持。
  不适用维度标“未涉及”并说明原因；有意打破惯例处说明理由并记录 DEC。
- **命令行提示流与 ESC/Undo 状态机**：
  - 经命令启动或包含视口拾取的功能，必须定义闭环状态机：入口与前置选择集（先选后执行 vs 先执行后选）、提示文案与关键字、默认值记忆规则、异常回显；
  - **异常与取消先行**：必须明确按 `ESC` 键或点击取消按钮后的界面恢复状态与图元数据回滚范围，以及 `Undo/Redo` 是一次性成组撤回还是分步撤回。
- **取值空间封闭**：暴露给终端用户的配置项、下拉枚举、数值参数必须完整列出取值空间（连续数值标明范围、步长、默认值与量纲单位；离散项完整枚举，严禁用“如”、“等”截断合法值集合）。
- **符号与工程文风**：
  - 逻辑判断与流程指向使用原生 Unicode 符号（≥、≤、≠、±、→、×）或程序符号（>=、<=、->），严禁使用 LaTeX 语法（如 `$\ge$`、`$\to$`）包裹常规符号；
  - 保持严谨、克制的工业工程文风，严禁出现营销浮夸词（如“极致体验”、“颠覆性”、“秒级响应”）或主观形容词（如“界面美观”、“操作友好”），一切要求必须转化为可观察的界面状态或可测试的参数判据；
  - 正文保持洁净室中立表述，使用通用工程术语（如“主流 CAD 宿主”、“传统实现”），不在 PRD 正文中直接点名外部商业竞品品牌（竞品对标细节留存独立分析记录）。

## 3. 内聚结构与编号引用约定

- **条目编号**：按类型稳定编号（FR 功能、BR 规则、AC 验收、NFR 非功能、DEC 决定／开放问题、RK 独立风险、SRC 来源）；帧 ID 使用 `FR-001-S1`。移动内容不重新编号，废弃编号保留记录且不复用。
- **单功能内聚闭环（废除跨章拆散）**：
  - 每个 `FR-xxx` 在第 3 章（及对应的 `features/FR-xxx/spec.md` 分片文件）内部**就地闭环定义其专属的交互卡、业务规则（`BR-xxx`）与验收标准（`AC-xxx`）**，不再把单个功能的规则和验收拆散到外部独立大章节；
  - 同一规则仅有一处完整定义，在表格首列内嵌锚点 `<a id="br-001"></a>`，跨处提及采用 `[条目名称（编号）](#锚点)` 引用。

## 4. 章节完备与流程图规范

- **核心章节**：合龙后的完整 PRD 包含第 1~3、6、7 章为核心章节（1. 背景、用户与目标，2. 范围与边界，3. 功能与交互规格，6. 风险与开放问题，7. 来源与参考资料）；第 4 章（数据、系统变量与接口）和第 5 章（性能与非功能要求）按需保留。出稿时清除模板占位提示。
- **业务总体流程（第 1.3 节）**：
  - 统一使用紧凑清晰的 **Mermaid 流程图（Flowchart）** 表达核心业务主干（控制在核心节点与分支内，避免巨型大图），或使用结构化步骤（输入 → 处理 → 结果）；
  - 图示资产通过 `scripts/render_mermaid.py` 渲染为本地静态 PNG 落盘至 `.assets/images/`，正文以标准 Markdown 相对路径引用；无可用浏览器时降级为结构化文本步骤并如实说明，不留断链。

## 5. 交互规格完备性

第 3 章每个 FR 的交互卡须满足以下可检验判据（Nova-Proto 原型构建与提炼方法见 [交互与原型设计](interaction-design.md)）：

- **交互卡必填**：每个 FR 必须包含交互卡。包含图形界面的功能采用 **以原型图为中心的状态走查卡**（置顶嵌入 `FR-xxx-Sx` 状态帧图 + ①②③ 标号走查 + `<cad-*>` 控件说明）；纯命令行交互可用经典状态事件表；确无交互的后台功能写 `交互卡：未涉及（具体理由）`。
- **图文与原型 100% 一致**：正文中的控件名称、`<cad-*>` 标签、默认值、枚举项与禁用联动必须与 `prototype.html` 及导出的状态帧图完全一致。
- **内聚验收挂钩**：交互卡中的关键状态迁移与异常回滚，必须被同一 FR 小节下方的 `AC-xxx` 验收表覆盖（Given 包含可构造样本，When 为明确动作，Then 为客观真值）；未决项登记 `DEC-xxx`。
