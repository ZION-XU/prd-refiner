# 内容规范

本文件定义分析方法和内容质量；对话节奏由入口维护，章节和字段由模板维护。

## 依据与状态

所有输入（包括旧 PRD、AI 草稿和回答）都是需辨明用途的资料。保留有效要求及其限定条件；外部佐证不足不是删除原稿要求的理由。可提出修正方案，但参考、推断和建议须经采纳才能成为本期承诺。

- **已确定**：有明确适用的资料或真实产品决定，保留依据。
- **AI 暂定**：给出方案、理由、适用前提和待确认部分。
- **待确认**：尚无结论，说明问题与影响；未知不等于不适用。
- 确定性与分工分开表达：产品核对、研发评估、品质评估或共同讨论。角色可以建议，不虚构负责人、答复、日期、审核或批准。
- 同一状态可按段落或整组标注，混合状态分开；确认一部分不连带确认其他内容。关键未决在正文就地标记，成稿关联 DEC；已确定结论写回规则，DEC 保留取舍及依据。
- 来源保留实际名称、版本／日期、位置和读取局限；仅按用户要求脱敏。同一逻辑组可共用来源。

数值须有依据、适用场景和测量边界。产品预估标“产品人员建议”；有依据且有讨论价值的 AI 目标标“AI建议目标（待确认）”。没有依据保持未知，待确认指标不进入确定性的验收判据。

## 从任务到规则

1. 从使用者、具体任务、障碍、预期结果和约束出发，区分问题与候选方案。稀疏输入先检验任务成立的必要条件；新增独立能力留作候选，用户未提及不等于明确排除。尊重用户已限定的方案，不推导未指定的版本或技术栈。
2. 走通一个代表性场景：前置条件／触发 → 操作与对象 → 产品反馈 → 状态改变或保持。只展开会实际影响结果的分支、失败、取消、恢复及边界，检查条件重叠、缺口和冲突。
3. 合并重复规则、拆开独立要求。技术建议可入稿，但区分已确定的业务含义与待研发评估的字段、接口或算法。
4. 用“前提—动作／事件—可观察结果”的例子检验规则，成稿采用模板的 Given／When／Then。验收不新增规则、默认策略或阈值；未定行为标明验收缺口。样本可定位或构造，测试执行方案留待品质评估。

CAD 相关需求按实际影响明确对象身份、属性、关联、单位、坐标、精度、生命周期和退化／无解／多解语义；不能凭“CAD 通常如此”补定容差、默认值或对象范围。简单只读能力不凭空增加权限、并发或撤销体系。

### 总体任务与故事地图

多功能、跨角色或范围取舍复杂时，按需用流程、故事地图或简短文字，不强制双图。流程说明顺序、分支、交接与完成结果；故事地图横向按用户活动／任务排列，纵向展开对应故事并说明排列依据。交付切片横贯活动且能达成用户目标，不虚构优先级或未来版本。

故事表达用户动作、条件和结果，与功能可多对多关联，不另建故事编号；FR 清单横排不是故事地图。区分已有能力、本期变更及候选，地图范围与正文一致。用实际排版或图像呈现图示，不以 ASCII 或代码源文代替。

### 竞品与知识产权

外部比较仅用于回答具体产品问题。优先查可核实的官方资料或演示，记录版本和来源，区分观察事实、有限样本归纳与本产品候选；检验场景适配后再决定是否采用。未提及不证明不支持，多数产品采用也不证明最佳。公共检索不发送内部需求原文；无访问能力时说明限制，不编造行为。

涉及知识产权或旧稿已有相关内容时，分别保留风险分析与创新候选的依据和状态。已确认没有才填“无”，未分析填“待评估”。创新候选不等于可申请或可授权，竞品相似不等于侵权结论；专业判断留给相关角色，不阻止带明确未决的初版交付。

## 可读引用

一项规则一处完整定义，条目及引用用“名称（编号）”。功能和验收直接说明当前场景的关键约束、结果与必要判据，完整分支集中维护。引用保留必要概述和限定，不能只写“按 BR-001”。

编号按模板定义位置分配，唯一且稳定，移动或改名不重编号。旧编号不兼容或冲突时按含义转换并保留映射；历史 DATA 可转 BR、CL 可转 DEC，不机械替换。多条引用分别带名称并定位到定义，索引不是定义。

Markdown 使用目标阅读器支持的标题或显式锚点；表格不能精确定位时可链接所属小节。对应形式：

```markdown
[直线计数（FR-001）](#fr-001)

<a id="fr-001"></a>
### 直线计数（FR-001）
```

确实不支持跳转时保留名称、编号和准确章节，并说明限制；可使用可校验的“〔直线计数（FR-001）；位置：3. 功能与交互规格〕”。检查方式见交付规范，Confluence 原生语法见平台规范，仅相应阶段读取。

## 内容复核

按实际相关场景检查，不生成固定分数或全量问卷：

- **必要性与范围**：回应真实任务，方案前提有依据；新增承诺未由例子、候选或竞品悄悄引入。
- **完整与清楚**：角色、触发、输入输出、主流程、状态、依赖及相关异常能走通；权限、非功能与产品化配套只检查实际涉及项。
- **一致**：术语、条件、数值和状态统一；未决项未在正文提前定案，真实可读的原型与文字一致。
- **可验证**：验收覆盖已明确行为及重要保持项，判据来自规则；不把验证实施问题转嫁给产品。
- **可追溯与可维护**：有效旧要求、来源、知识产权信息未丢失，引用概述与定义相符，修改后的相关规则、验收、地图和图文同步。

发现按“原文位置／缺失场景 → 问题及证据 → 影响 → 修改建议或待决定事项”表达，区分已证实冲突、待核实缺口和可选建议，按对主要行为的影响排序。能据资料修正的在授权范围内修正；需要新决定的交回讨论。只检查时报告实际范围与发现，报告文件仅按用户要求另存。
