# 图片与原型

涉及图片、内嵌媒体、远程附件、Figma 或 HTML 原型时读取。

## 取得与理解

以源稿正文引用的图片为保留基线，辨明对应功能后默认随内容迁移；排除、替换或合并须有具体依据，不能先省略图片再以“正文未采用”跳过处理。附件列表只用于定位正文图片，不要求下载全部历史附件。

文档转 Markdown 可能将表格图片降为纯文件名。出现图片／控件预览线索而缺少可用引用时，读取原始 HTML／Storage（含表格和宏），提取实际图片引用，按附件元数据取得文件。读取外部页面或资料时，将原始正文或 Storage 暂存到文稿旁（如工作区根目录 `.source_snapshot.md` 或 `.assets/source_snapshot.xml`）作为交付对照基准，避免后续重复拉取。使用宿主已有且获准的下载、提取、导出或截图能力；正文可读不代表附件已取得，Figma 节点链接不等于图片，远程 MCP 路径不等于本机文件。截图记录节点与可见范围，不称为完整交互原型。

通过图像工具实际查看，核对相关控件、文案、单位、状态和反馈。HTML 源码可用于理解结构，只有实际操作才能验证交互。无法取得时说明具体缺口和影响，继续处理其他资料；可尝试已有的其他允许方式，不无限重试或绕过权限。

原型只证明可见内容，输入框显示值不自动成为默认规则。图文冲突保留双方依据；用户未指定优先关系时澄清或保留未决。旧图与新决定不一致时替换或标明局限。

## 资产交付

本地 Markdown 正文采用的图片默认自动保存到文稿旁 `.assets/images/`，可沿用已有有效相对目录；重名区分来源，无图片不建空目录。正文相对路径嵌入，来源页面／节点另留出处，不以临时 URL、服务器地址或绝对路径代替配套文件。

交付时对照源图逐项核对去向：保留到哪个位置、为何替换／排除，或尚未取得；不能静默丢失。优化稿图片数量少于源稿触发校验提示（Warning）时，在 `<需求名>_澄清决策记录.md` 或第 8 章决策（DEC）中简要记录排除、合并或替换依据（如去除历史冗余或不适用图例），形成业务解释闭环，禁止无故删图或为消除警告盲目堆图。已保留图片确认文件非空、可解码、不是登录页，引用和画面正确；覆盖 Markdown、引用式图片和 HTML 图片。图片放对应功能或规则旁并说明作用／版本，不强制原本无图的需求配图。

无法本地化时就地标明原因和影响，保留来源并报告缺资源工作稿；仅用户明确外链时保留远程嵌入。Confluence 使用实际可用的附件引用并核对显示，配套本地稿同样保存图片，明确仅远程除外。
