# 图片与原型

涉及图片、内嵌媒体、远程附件、Figma 或 HTML 原型时读取。

## 来源快照

Confluence 来源首次读取时，由宿主调用 `confluence_get_page` 的原始格式与元数据能力取得正文、页面 ID 和版本；解析正文中的 Markdown、HTML、附件宏及跨页附件来源后，使用 `confluence_get_attachments`（按需分页或按文件名定位）和 `confluence_download_attachment` 下载每个正文所引图片。宿主提供等价批量下载能力时可以合并调用，但必须把返回的 Base64／资源内容实际保存为本地文件，不能只保留 MCP 响应、附件名或远程地址。

下载完成后运行 `scripts/build_snapshot.py` 做本地封装和完整性校验。该脚本不连接 Confluence，也不接收或保存 PAT；只有返回 `passed: true` 且 `manifest.json` 为 `complete` 才能进入分析或格式转换。本地稿必须从快照的 `source.md` 生成，无图的接口正文和临时 Markdown 均不能替代快照。

快照缺图、文件无效、路径不安全或页面元数据不全时停止依赖该来源的成稿和写入，报告具体缺口；不能退回无图正文继续宣称完整。完整快照保留原始正文、本地引用正文、页面元数据及图片哈希清单。后续分析、澄清、成稿及图文核对只读该快照；写入前另核对最新版本，写入后回读。附件列表只用于定位正文图片，不下载无关历史附件。

## 理解与交付

实际查看相关图片，核对控件、文案、单位、状态和反馈；原型只证明已观察到的内容，静态图不证明交互，输入框显示值不自动成为默认规则。无法取得时说明缺口和影响，继续处理不依赖该图片的内容。

以快照清单中的源图为对照，逐图记录保留、替换、排除或未取得状态。该清单作为内部交付门禁；只有发生替换、排除、缺失或产品取舍时，才在修改说明、澄清记录或 PRD 相关位置说明，不要求把完整对账表写入正文。

发现图文冲突时说明图片和正文位置、具体差异及影响；需要改变产品含义时交由产品决定。未决只冻结受影响内容，不阻止其他独立工作或带未决出稿。旧图与新决定不一致时按决定替换、排除或标明局限，并更新清单。

本地成稿采用的图片保存到 `.assets/<需求名>/images/` 并实际查看，正文用相对路径引用；用户明确指定其他位置时遵循其要求。不能以临时 URL、服务端路径或非空文件冒充有效图片。图片在正文中就近放在对应内容旁；无图需求不强制配图。Confluence 使用有效附件引用并核对显示，明确仅远程交付时可省略本地配套稿。
